# Industrial AI Sales Platform

跨境工业品 AI 售前平台：收集买方画像与工况，引入有据可查的 chatbot，完成产品推荐、人工接管、RFQ 和销售跟进。

## 项目状态

首个应用切片已经加入：产品资料登记、来源文件元数据/上传、字段候选值核对、人工核准、产品版本发布、撤回和公开买方产品页。第二个切片已加入买方询盘、需求摘要确认和可解释水泵匹配。第三个切片已加入资料内有据问答、引用来源和资料外问题人工接管。第四个切片已加入 RFQ 询价、需求/推荐/产品版本快照和待补充状态。第五个切片已加入销售工作台，可维护负责人、阶段、跟进日期、备注并查看全链路上下文。管理端认证已支持本地演示会话、角色权限和管理员成员管理，可创建或停用本企业后台账号。

## 本地启动

项目只使用 Python 标准库和 SQLite，Python 3.9+ 即可启动：

```bash
python3 app.py
```

打开 `http://127.0.0.1:8000/admin`，管理员点击“加载演示数据”即可从项目内的 `fixtures/demo_seed.json` 加载完整演示工作区：两款已发布水泵、一个完整 RFQ、一个待补充 RFQ、一条销售跟进和一条待处理人工任务。产品管理页的“加载 Lowara 资料”会从 `fixtures/lowara_demo_seed.json` 加载用户提供的 `B2B_Pump_Demo_Research/Lowara` 结构化数据，包含 `3SV08NL007T`、Rev. B 第 24 页目录性能点、来源文件元数据和授权待确认提示；源 PDF/CAD 不会在未确认授权前复制进仓库。重复点击不会复制已有记录。然后打开 `http://127.0.0.1:8000/inquiry`，用英文或中文描述流量、扬程和介质，检查摘要后点击确认匹配；Lowara 目录性能点只做透明初筛，结果会保留“需工程确认”。演示数据库默认写入 `data/app.db`，上传文件写入 `data/uploads/`；两者均为本地运行数据，不应直接用于真实客户资料。

M3/M4 当前使用标明为 `pump-demo-v1` 的确定性演示规则：只读取已发布产品版本；流量、扬程和介质是匹配必需条件；结果会列出满足项、冲突项和未知项。带目录性能点的型号会用线性插值做屏幕初筛，但只显示“需工程确认”，不会把未知条件当成满足。M5 的资料内问答只读取同一已发布快照并显示文件/位置/版本；价格、库存、交期、认证和资料外问题会转入人工任务。M6 的 RFQ 会保存提交时的需求、推荐、产品版本和联系信息快照；缺数量、目的地、交期或邮箱时标记为待补充，不标记为可报价。M7 的销售工作台通过 `leads` 关联 RFQ，支持阶段、负责人、下一步跟进日期和备注，并在详情中展示需求、推荐、问答、人工任务和操作记录。规则不是正式工程选型标准，后续应由产品负责人/工程师确认。

运行测试：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v
```

后台现在有本地演示登录和角色权限：`demo-admin@example.invalid`、`demo-sales@example.invalid`、`demo-engineer@example.invalid`，密码分别与账号前缀 `demo-admin`、`demo-sales`、`demo-engineer` 相同。管理员登录后可从 `/admin/users` 创建或停用销售、工程师和管理员账号；停用会立即使该账号的现有会话失效。登录会话保存到 SQLite，企业上下文从会话读取；这些账号和密码只适合本地演示，不能视为生产身份系统。生产部署前仍需接入正式身份、密钥管理、密码策略和多企业账号管理。

## 开发原则

先完成可验证的 MVP 主流程，再按影响处理问题。产品事实、买方数据和人工判断分开保存；页面、匹配和 chatbot 使用同一份已核准产品版本。
