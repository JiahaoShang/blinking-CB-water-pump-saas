# Industrial AI Sales Platform

跨境工业品 AI 售前平台：收集买方画像与工况，引入有据可查的 chatbot，完成产品推荐、人工接管、RFQ 和销售跟进。

## 项目状态

首个应用切片已经加入：产品资料登记、来源文件元数据/上传、字段候选值核对、人工核准、产品版本发布、撤回和公开买方产品页。第二个切片已加入买方询盘、需求摘要确认和可解释水泵匹配。第三个切片已加入资料内有据问答、引用来源和资料外问题人工接管。第四个切片已加入 RFQ 询价、需求/推荐/产品版本快照和待补充状态。第五个切片已加入销售工作台，可维护负责人、阶段、跟进日期、备注并查看全链路上下文。

## 本地启动

项目只使用 Python 标准库和 SQLite，Python 3.9+ 即可启动：

```bash
python3 app.py
```

打开 `http://127.0.0.1:8000/admin/products`，点击“导入两款示例水泵”，再逐个进入产品完成字段核对、核准和发布。然后打开 `http://127.0.0.1:8000/inquiry`，用英文或中文描述流量、扬程和介质，检查摘要后点击确认匹配。演示数据库默认写入 `data/app.db`，上传文件写入 `data/uploads/`；两者均为本地运行数据，不应直接用于真实客户资料。

M3/M4 当前使用标明为 `pump-demo-v1` 的确定性演示规则：只读取已发布产品版本；流量、扬程和介质是匹配必需条件；结果会列出满足项、冲突项和未知项。M5 的资料内问答只读取同一已发布快照并显示文件/位置/版本；价格、库存、交期、认证和资料外问题会转入人工任务。M6 的 RFQ 会保存提交时的需求、推荐、产品版本和联系信息快照；缺数量、目的地、交期或邮箱时标记为待补充，不标记为可报价。M7 的销售工作台通过 `leads` 关联 RFQ，支持阶段、负责人、下一步跟进日期和备注，并在详情中展示需求、推荐、问答、人工任务和操作记录。规则不是正式工程选型标准，后续应由产品负责人/工程师确认。

运行测试：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v
```

当前登录和企业成员权限仍是下一切片前必须补齐的开发项；本地演示固定使用 `demo-tenant`，不能视为生产级租户隔离或身份认证。

## 开发原则

先完成可验证的 MVP 主流程，再按影响处理问题。产品事实、买方数据和人工判断分开保存；页面、匹配和 chatbot 使用同一份已核准产品版本。
