# 企业知识管理 · 第二批设计评审原型（文件入库 + 灵活字段）

> **状态：第二批设计评审原型 · 演示数据。设计范围已由用户确认（2026-10-11：「文件入库＋灵活字段一起设计」）；详细规则仍待评审；未开始第二批业务代码开发。**
> 配套 PRD：`docs/企业知识管理-PRD与交互设计-v0.2-第二批评审稿.md`（由 Codex 维护）。
> 第一批设计保留：`design/enterprise-knowledge-prototype/`（本原型不修改它）。

- 原型性质：纯前端（原生 HTML/CSS/JS，无依赖、无外部请求）。**所有数据只在浏览器内存里，刷新或关闭即重置。**
- **不读取文件内容、不上传、不调用模型、未连接后端。** 演示里的识别、保存、发布、模板版本都是预置数据与前端状态变化。

## 怎么打开

方式一：直接双击 `index.html`（或拖进浏览器）。

方式二（本地固定地址，评审约定端口 18872）：

```
python3 -m http.server 18872 --bind 127.0.0.1 --directory design/enterprise-knowledge-phase2-prototype
http://127.0.0.1:18872/
```

## 5 分钟体验路径（建议按顺序）

1. **文件资料列表**：三条代表性内容——「客户服务政策」（已发布 v2，AI 客服可用·绿色）、「新员工培训资料」（草稿）、以及「扫描版产品手册」在**导入记录**区（任务进度「无法识别」+ 原因；导入任务进度不是知识状态，知识生命周期只有 草稿 / 已发布 / 已停用）。搜索出现「×」——点击只清关键词，形态/状态筛选保留、焦点回到搜索框。
2. **上传文件（三步）**：文件资料视图右上「上传文件」→ 第 1 步选模板（可点「演示样例：PDF / DOCX」，或选本地文件——只记录文件名，不读取内容）→「开始核对」→ 第 2 步。
3. **核对页**：左侧「原文示例 · 非真实 PDF 渲染」有第 1/2 页切换；点右侧任一「来源 · 第 x 页」会跳到对应页并高亮。正文逐段「包含该段 / 确认已核对」，改文字会重置核对并标「人工修改」；一个段落标着「待核对」（表格断行提示，不保证内容正确）；一个段落是「仅内部」（默认不勾选包含）。演示：把「仅内部」段落勾选包含 → 出现处理提示（排除内部段落 / 整条改为内部）。
4. **字段映射（手动）**：段落上点「用作字段值…」→ 选「服务时效」→ 值/单位/来源页可改 → 填入。字段默认「未核对、未允许客户问答」；必填空着**只挡发布**（「发布」按钮禁用并写明原因），「保存草稿」随时可用；数字 0、「否」都算已填写。
5. **发布/草稿**：第 3 步有发布检查清单与「演示场景」控件（发布后处理正常 / 处理失败）。对外 + 已授权发布会弹原生确认框（列出用途、AI 使用范围、有效期）；内部或未授权发布不多一步。选「处理失败」发布 → 详情页显示蓝灰「已发布（AI 客服不可用）· 处理失败」可重试（把场景切回正常再点重试即可恢复；原型不用计时器模拟）。
6. **替换文件（版本）**：打开「客户服务政策」→「替换文件…」→ 载入演示样例（对照区列出「文字有变化 / 新增段落 / 未匹配」——只是文本对照，不做语义判断）→ 保存草稿：旧 v2 继续可用，详情出现「替换文件草稿」；「继续编辑草稿」→ 发布 → 变 v3；发布失败也不回退旧版。
7. **来源与版本**：详情页「来源与版本」页签有 v1 / v2 / v3；「恢复为草稿」只创建新草稿，不覆盖历史（v1 有演示快照）。
8. **知识模板**：侧栏「知识模板」（仅管理员视角可见）→ 编辑「服务方案模板」：改名/改类型/必填/单位/选项、上移下移、删除、添加，右侧实时预览；保存 → 差异确认 → 新版本。演示规则：改名保留已填写的数据；**改类型需要重新填写（历史与来源中的旧值保留）**；移除字段的旧值保留在历史与来源。
9. **采用新版模板**：打开「上门安装服务方案」（正在用 v1，已有 v2）→ 字段页「采用新版模板（v2）…」→ 对照新增/移除/必填 → 确认生成升级草稿（旧值保留、新字段留空），发布前线上版本不变。取消不改任何值。
10. **未保存保护**：在核对页或模板编辑器有改动时点其它导航 → 弹「未保存的修改」（保存草稿并离开 / 放弃修改并离开 / 继续编辑）；模板编辑器只有放弃/继续。Escape 取消、焦点回到原按钮。
11. **只读视角**：顶栏切「仅阅读成员」——无上传、编辑、模板入口；正文/字段/来源/历史仍可读（含仅内部资料）。这**只演示界面差异**，真实权限必须由后端强制。
12. **手机尺寸**：缩到 390（或 320）宽——侧栏变抽屉、核对页双栏堆叠为上下、字段变为卡片而不是宽表格、标题占满整行不横向溢出。

## 演示边界（务必了解）

- **文件识别**：不读取任何本地文件；「演示样例：PDF / DOCX」直接给出预置识别结果，五种「演示场景」（识别成功 / 扫描件 / 旧版 DOC / 加密 / 损坏）由评审控件直接切换，**没有用倒计时冒充处理过程**。
- **发布结果**：「处理正常 / 处理失败」也是演示场景切换；真实系统的识别与处理是后端异步任务，失败原因与重试以真实实现为准。
- **字段**：只支持 文字 / 数字+单位 / 选项 / 日期 / 是·否 五种类型与简单列表排序；**没有**公式、跨字段换算、重复组或字段间关联。
- **映射**：段落→字段完全是手动选择与手填；原型不演示、也不承诺「自动识别字段」。
- **权限**：视角切换只演示界面隐藏，未验证后端隔离；模板管理沿用「管理员 / 产品管理授权成员」是评审建议（P2-02），未实现。
- **导入限制**：≤10MB / ≤200 页是评审建议（P2-05），原型只是文案提示，不做真实校验。

## 设计范围（已确认）

用户已确认的设计范围（2026-10-11：文件入库＋灵活字段一起设计；与 PRD v0.2 第 3 节一致）：文字 PDF / DOCX 的识别与来源位置整理；扫描件 / 旧 DOC / 加密 / 损坏的人工整理回退（**不含 OCR 实现承诺**）；单文件导入与导入记录；知识模板与简单自定义字段、模板版本与已有知识的人工升级；段落→字段的手动整理与来源标注；替换文件与新草稿、版本比较、历史恢复为草稿。

**不包含**：网页导入、API/CRM 同步、Agent 单独授权、复杂 PIM/DAM、公式与字段关系、自动对外发布、自动数值推断、扫描件 OCR 正式实现、批量迁移历史资料。交互与规则待评审；业务代码未开始。

## 已知演示限制（不承诺已验证）

- 识别结果是预置演示文本；对照只按段落顺序简单对应，不代表语义判断或「冲突」结论。
- 「恢复为草稿」只有部分版本带快照（演示限制）；草稿暂不支持删除。
- 停用/启用的确认范围按评审建议实现；「重新启用」后 AI 可用性取决于授权与处理结果（本原型直接置为已发布，不带真实处理）。
- 模板版本、字段历史等均在内存中，刷新即重置；不构成持久化设计证据。
- 问答测试沿用第一批设计，本原型不重复实现（侧栏入口为说明页）。
