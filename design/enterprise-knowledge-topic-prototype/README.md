## 体验路径（建议按顺序走，约 5 分钟）

1. **默认全部主题**（左栏「全部主题」）：按分组（产品与交付 / 团队与文化）分区展示，另有「未分组」。左侧主题导航里的分组默认收起——展开「产品与交付」看折叠动画与键盘行为（收起时子项不可聚焦/读屏跳过）。搜索支持主题名与正文关键词，清空"×"只清关键词。
2. **主题详情**：打开「智能会议设备A」——正文（介绍、要点）优先，每条都有来源（如"《会议设备A-产品规格书.pdf》· 第 2 页"）；点来源直接跳到资料详情并高亮对应位置。「关联资料」「相关主题」「关系视图」「版本记录」默认折叠、按需展开（标题带数量）。从来源跳到资料后，「返回主题「智能会议设备A」」回到主题且关联资料自动展开；连续「返回」会逐层回到最开始进入的入口（例如带筛选的全部资料），筛选不丢。
3. **同一主题多形式资料**：主题详情「关联资料」里可以看到 PDF / DOCX / 图片 / 视频 / 网页 / 手动正文六种形式；图片、视频、网页点开后是「仅登记原件」——不会显示伪造的识别成功；「状态与关系」一栏把发布状态、识别状态、用途、AI 可用原因分开写明。试试「更多操作 → 补充手动正文」给照片人工写一段（会标注「人工撰写」）。
4. **全部资料统一入口**：左侧「全部资料」——搜索 + 形式 / 主题 / 状态三个独立筛选；输入关键词后搜索框即时出现"×"，点击只清关键词、保留筛选、焦点留在搜索框；「未关联主题」筛选能看到归档里未关联的资料（如 2024 年产品目录，已停用）。
5. **添加资料三步**：左侧「添加资料」→ 第 1 步可以真实多选文件（只显示名称与大小，不读内容不上传）、登记网页地址、添加手动文字；不想准备文件就展开「载入混合示例」（PDF、DOCX、图片、视频、网页各 1 件）→ 第 2 步：先点**「使用示例整理结果（演示）」**（这是评审控件：图片/视频/网页仍是"仅登记"）→ 每件资料默认折叠，第一件有正文的自动展开「检查正文」：勾选「已核对」（剩余数量实时更新），编辑会标记"人工修改"并撤销该段核对；可"＋添加段落"，新段落需要选择来源；其他资料与「调整主题」按需展开 → 在同页核对系统建议的主题：改名、合并到已有、拒绝、撤销、追加、整批设置共同主题（**同批同名的新主题建议会合并为一个**）→「确认主题与关联」（确认前新主题不会出现在左侧导航；确认后会以草稿出现）→ 第 3 步「发布设置」：用途 / AI / 到期唯一位置，默认对内 + AI 关；未通过项会列出并可"去处理"。**保存草稿**允许不完整；**发布**（对外 + 开 AI 时会先弹确认）后回到全部资料，能看到刚发布的资料与结果；新主题为草稿，正文初稿待核对后发布。
6. **更新资料（版本）**：打开《会议设备A-安装指南.docx》→「更新资料」→「载入更新示例（演示）」→ 对照页看"文字有变化 / 新增段落 / 保留人工修改"（成员此前的人工修改不会被静默覆盖）→ 勾选核对后「发布新版本 v2」；旧 v1 保留在「版本记录」。也可以「保存更新草稿」，当前发布版本继续有效。
7. **手动新建主题**：全部主题右上「新建主题」→ 建立后是草稿；「编辑正文」里可用「根据关联资料整理初稿（演示）」附上系统初稿（每段标出确切来源、默认"待核对"，不会覆盖已有内容），逐段勾选「已核对」并保存后「发布主题」；正文为空或还有未核对段落会被拦下。
8. **分组管理**：全部主题右上「管理分组」→ 管理模式出现「新建分组」按钮（可给新分组起名）；也可改名、删除分组（主题保留为未分组）、逐条把主题"移动到…"某个分组。
9. **只读视角**：顶栏切「仅阅读成员」——可阅读、搜索、返回、跳转；添加、编辑、发布、关联调整入口全部隐藏（界面差异演示，真实权限由后端强制）。
10. **未保存保护 / 键盘**：核对页或主题编辑有改动时点其他导航 →「未保存的修改」（保存草稿并离开 / 放弃 / 继续编辑）；Escape 关闭对话框并回到触发按钮；缩到 390/320 宽用手机布局走一遍。

## 演示边界（务必了解）

- 常驻只有「设计预览 · 演示数据，刷新重置」；其余评审/权限/技术说明折叠在「预览说明」。
- **识别**：不读取任何本地文件；「使用示例整理结果（演示）」把预置示例文字填入文字型文件；图片 / 视频 / 网页保持"仅登记原件"。**没有用倒计时或其它方式冒充真实处理。**「重试识别」只记录演示提示，不改变状态。
- **保存 / 发布**：只改变浏览器内存里的演示数据（刷新重置）；"发布成功"不代表后台处理完成。真实识别、解析、保存、AI 证据过滤由后端实现。
- **权限**：视角切换只演示界面隐藏，未验证后端隔离。
- **更新对照**：「保留人工修改 / 差异对照」为设计建议（PRD §12 P3-06），对照文本为示例，不渲染真实文件；仅《会议设备A-安装指南.docx》有一条演示样例，"选择文件"只登记文件名。
- **关系视图**：小型局部关系列表（设计建议）；没有全局图谱。**分组**不限制跨主题关联。
- **到期**：北京时间按固定 UTC+8 比较；不填 = 长期有效。
- **字段**：只支持文字 / 数字 + 单位两种类型的少量字段，每个字段要求写出来源；无公式、无自动换算、无模板选择（模板管理本原型未覆盖）。
- **主题正文初稿**：「根据关联资料整理初稿（演示）」只复制已核对文字段落的第一段及其确切出处，不调用模型、不推测图片/视频；初稿默认「待核对」，核对后由成员发布。

## v0.3 修订记录（2026-10-12，评审前小修订）

3. 返回上下文改为轻量内部返回栈：全部资料（带筛选）→ 主题 → 来源资料 → 逐层返回不再丢入口；主题 → 相关主题 → 来源资料同理；不依赖浏览器历史、不引入路由库。
4. 新主题初稿语义修正：资料发布时不再把初稿标成「已核对」；新主题保持草稿并在编辑页显示「系统初稿（待核对）」与出处，勾选「已核对」后才可发布主题；新增显式「根据关联资料整理初稿（演示）」（主题页草稿空态 + 编辑页），已有/手动新建主题同样可用；只追加不覆盖人工修改。
5. 状态双标签统一：主题列表/详情与资料一致使用「已发布（AI 客服可用）」绿 / 「已发布（AI 客服不可用）」蓝灰（附原因），草稿保持生命周期标签。
6. 同批同名新主题建议合并为一个主题（单项仍可取消关联）；批次提交（保存草稿 / 发布）增加一次性防护，不会生成重复资料。
7. 搜索「×」修复：输入关键词后即时出现、清空后即时隐藏；只清关键词、保留其他筛选、焦点留在搜索框（不再整页重渲染丢焦点）。

### 第三轮修订（2026-10-12，真实浏览器复现阻断项）

Codex 真实浏览器复现 3 项阻断，本轮为针对性修复（未扩展范围）：

1. **对话框按钮无响应修复**：统一点击派发最前处理 `data-dlg` → `state.dlgActions[index].onClick`；动作返回 `keep` 保留对话框（如校验失败），其它情况（含未定义回调的「取消」）执行后关闭；确认 / 取消 / Escape / 焦点恢复可用，未使用原生 alert/confirm。
2. **核对数量实时更新**：勾选「已核对」只更新该资料的剩余数量标签与折叠标题（全部核对显示「已核对」）；编辑正文会撤销该段核对并同步数量；仅局部 DOM 更新，不整页重渲染，输入焦点与已展开区域保留。
3. **入库页紧凑化**：第 2 步每件资料改为紧凑列表 + 按需展开「检查正文」（显示剩余数量）与「调整主题」（标题带建议摘要）；默认只展开第一件有正文的资料（使用示例整理结果后同样如此），仅登记资料只显示名称、格式与关联信息；字段始终为折叠选填；整批共同主题与集中确认保留，系统建议仍需确认、核对要求不减少。

### 第四轮修订（2026-10-12，主流程阻断）

Codex 复现 3 项主流程阻断，本轮针对性修复：

1. **第 3 步设置区丢失修复**：`captureStep3HTML` 中用途 / AI / 到期三段字符串此前是「被丢弃的表达式」（缺少 `h += '<div class="card">` 前缀）→ 恢复正确拼接与容器闭合；第 3 步现在完整渲染 `w-usage` 单选、`w-ai` 开关、`w-expiry` 输入。
2. **「下一步：发布设置」点击链路**：真实派发核验 `c-next2`（含 `c-to-step2` / `c-back`）分支在统一派发中可达，第 2 步→第 3 步正常渲染。对真实浏览器中底部右侧按钮点击无效的现象：与右下角常驻 Toast 固定层覆盖按钮位置的机制一致（提示层默认可接收指针事件、盖住约 380px 的右下角区域），本轮为 `.toasts` 增加 `pointer-events:none`，提示在任何位置都不再拦截点击。
3. **移动抽屉**：明确点击侧栏导航目标（全部主题 / 全部资料 / 添加资料 / 问答测试 / 主题项）后关闭抽屉；分组展开 / 收起不关闭；Escape 收起并把焦点还给菜单按钮；桌面端无行为变化。

### 第五轮修订（2026-10-12，小修复）

1. **分组管理新增「新建分组」入口**：管理员进入「管理分组」模式后，工具栏出现清楚的「新建分组」按钮（连接既有 `group-new-open` 与既有对话框 / 名称校验，未新增函数或库）；普通阅读成员不可见。此前源码有处理分支但没有任何入口按钮，创建分组无法完成。
2. **手动文字识别标记修正**：添加手动文字的资料此前被归为「未能识别」（`newWorkItem` 的兜底分支误伤 `format=manual`）→ 现在识别标记为「人工正文」；第 2 步资料头显示「人工正文 / 人工正文 · 待核对 N 段」（核对后回到「人工正文」），不再把人工录入描绘成识别失败。人工出处（来源=人工撰写）、核对、AI 授权与发布闸门（缺名称 / 无正文仍被拦）保持不变。
