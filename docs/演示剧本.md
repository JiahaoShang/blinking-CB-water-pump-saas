# 演示剧本（对外演示 / 内部彩排通用）

**适用**：向试点企业展示或内部彩排。全部步骤已在 2026-10-03 于本机「全新演示库」上完整走通，截图见 `data/evidence/demo-readiness-2026-10-03/`（01–19）；2026-10-03 增补第二个可比型号后重新实测，证据见 `data/evidence/attribution-revision-demo-model-2026-10-03/`。
**核心话术（一句话）**：这不是「AI 猜答案」，而是「**只从企业已核准的资料里回答，带出处；资料外的问题交给人工**」。
**演示数据边界**：演示库包含两个可比合成演示型号 SLICE-T1 / SLICE-T2（运行范围不同，可并列成为候选）与无水力依据对照型号 SLICE-NOBASIS；所有型号名、来源文件名、字段出处与文件内容都标注 DEMO 合成演示，不对应任何真实在售产品，演示时不得引用为厂商规格或承诺。

## 0. 准备（约 2 分钟）

```sh
cd "<仓库根目录>"
python3 tools/demo/start_demo.py        # 首次自动构建演示库；自动打开两个浏览器窗口
```

- 左侧窗口 = 买方官网聊天（`/reference-client?site_key=demo-site-key`）；右侧窗口 = 卖家系统（`/admin`）。
- 演示账号：管理员 `demo-admin@example.invalid / demo-admin`；销售 `demo-sales@… / demo-sales`；工程师 `demo-engineer@… / demo-engineer`。
- **状态重置**：Ctrl+C 停止 → `python3 tools/demo/start_demo.py --reset`（演示库重建，演示中产生的数据全部清掉）。
- 端口被占用时：`--port 8138`（买方窗口用 `?site_key=demo-site-key` 重新连接即可）。

## 1. 买方旅程（约 6 分钟）

**Step A 描述需求 → 推荐（开场主打）**
聊窗连接（**打开即见欢迎语**，按系统语言中/英文，右上角按钮可切换）→ 在底部输入框输入 `flow 50 m3/h, clean water, head 45` → 出现「请核对提取的工况」卡片 → 点「确认工况」→ 点「查找产品」。
预期：**SLICE-T1 与 SLICE-T2 两个候选并列可初步推荐（有依据）**，各自列出满足项（含该型号的产品范围差异，如 30-90 / 20-60 m³/h）与独立详情页链接；SLICE-NOBASIS（无水力依据的型号）从不出现。
话术：>*"每个事实都带出处；两个型号的运行范围不同，差异直接列在旁边。没有确认过的信息，系统不会拿去做推荐。它们都是标注 DEMO 的合成演示数据，不会冒充厂商规格。"*

**Step B 缺口场景（展示"不装懂"）**
新会话发 `flow 50 m3/h, clean water`（故意不给扬程）→ 确认 → 查找产品。
预期：**条件不足** + 两个选择：「查看待核实候选」与「请求工程师协助」。点「查看待核实候选」→ SLICE-T1 与 SLICE-T2 都标注**待核实（未确认适用）**，并显示「买方尚未确认扬程」。
话术：>*"不确定就不装确定；就算点开，每一个都标着'待核实'。"*

**Step C 冲突场景（展示"不硬推"）**
新会话发 `flow 50 m3/h, clean water, head 300` → **无可靠候选**（300 m 超出两个型号的扬程范围，全部硬冲突）。
话术：>*"已知冲突的型号绝不会被当成候选。宁可说没有，也不推错货。"*

**Step D 独立产品页（两个候选各有一个链接）**
在推荐结果里点任一候选的产品链接 → 独立详情页（两个链接分别打开各自型号的页面）：图库缩略图切换、二维/三维/资料专区（STEP/DXF 为**原件下载**，PDF 可预览）、每个事实带出处（含 DEMO 标注）、页内「对比已发布型号」表格可直接看到两个型号的范围差异。
话术：>*"买方看到的就是这个版本；企业改资料后重新发布，旧询价仍对应旧版本快照——不会张冠李戴。"*

**Step E 提问（有据回答 vs 人工接管）**
在底部输入框直接提问 `What is the flow range?` → **有出处回答**（回答卡标注所依据的型号并引用参数表）。
需求描述与提问共用同一个输入框：带问号/疑问词的自动按「产品问答」处理（绑定当前推荐型号），其余按「需求识别」处理。
再问 `Can you confirm the price and delivery time?`（资料外）→ 保存为待核实 → 点「请求工程师核实」。

## 2. 卖家侧（约 5 分钟）

**工程师回合**（右侧窗口登录 `demo-engineer`）：
任务列表 → 打开任务 → 用「追问」字段向买方提问（左侧窗口出现**工程师追问**并给出回复框）→ 买方回复后，工程师填写答复送出 → 左侧窗口出现**工程师回复**（带标签）。
话术：>*"买方从头到尾不用离开原会话，也不用留联系方式。"*

**销售回合**（登录 `demo-sales` 或 `demo-admin`）：
销售工作台列表 → 打开线索详情：
- 销售点「**领取这条会话**」/ 管理员用「**分配或改派**」（两者都已实测）；
- 「缺项清单」「买方已修改 N 次」横幅、「记录并停止主动跟进」（停止后不再主动联系）；
- RFQ 详情页有「**变更内容（相对上一版）**」逐字段对比（演示中数量 2 → 3）。

## 3. 收尾与常见问题

- *"数据在哪？"* —— 隔离在企业自己的库里；文件逐份许可、发布时冻结清单。
- *"为什么可信？"* —— 一切带出处；未核准不进入匹配、问答与公开页；资料外的只会转人工。
- *"没做出来的部分？"* —— 如实说明：对外试点前还需按 `docs/试点就绪核对表.md` 完成 9 项检查（真实授权、真实域名、恢复彩排等）。

## 4. 备用动作（万一）

| 状况 | 处理 |
| --- | --- |
| 页面状态乱了/想重来 | Ctrl+C → `start_demo.py --reset` → 重开两个窗口 |
| 端口占用 | `--port 8138`，窗口地址改为 `http://127.0.0.1:8138/...` |
| 聊天窗口没连上 | 检查网址带 `?site_key=demo-site-key`；点「连接」重试 |
| 演示中断需快速恢复 | 重新运行 `python3 tools/demo/start_demo.py`（数据都在演示库里，不会丢） |
