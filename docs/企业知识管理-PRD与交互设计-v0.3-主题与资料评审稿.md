## 1. 这版改了什么、为什么

v0.1/v0.2 把企业知识分成「产品与服务 / 文章与 FAQ / 文件资料」三个入口。用户实际使用后指出：这是把**内容组织形式**（正文、问答）和**来源形式**（文件、文章）混在一起导致资料找不到、关系对不上——一份安装指南既讲产品又属培训，归到任何一类都不对。

v0.3 把知识组织成两个**独立维度**：

- **资料形式**（PDF、DOCX、图片、视频、网页 / 在线文章、手动正文）：资料"是什么形式"。
- **内容主题**（如：智能会议设备A、售后标准、入职培训、企业文化）：资料"讲的是什么事"。

任意形式的资料可以关联任意主题，一份资料可以关联多个主题；一批不同格式的资料可以围绕同一主题。**有关系才建立关联，不做"全部连接"**。主题成为主要浏览入口：主题页承载完整知识正文（介绍、要点、出处）与关联的原始资料。

## 2. 已确认规则（用户 2026-10-12 已明确，不再重复询问）

1. 资料形式与内容主题是独立维度（见上）；实际有关系才建立关联。
2. 主题是主要浏览入口；主题页 = 主题知识正文 + 关联原始资料；参考 Obsidian 的阅读中心、大纲与反向链接的**使用感**，但不要求用户懂 Markdown、插件或文件夹操作。
3. 主题支持**可选的自定义分组**：分组只辅助导航，可创建、调整、删除或不使用；分组不限制跨主题关联，也不给企业强制行业分类。
4. 关联建立方式：**系统建议、用户确认后建立**；用户可改名、合并到已有主题、拒绝，并可随时直接创建主题、调整关联。未来"系统直接自动关联"为后续候选，不是当前正式行为。
5. 主题正文由系统根据**能识别的**资料整理初稿并标注出处；用户修改/确认后发布。没有可靠依据时留空或提示补充，不猜关键事实。
6. 交互目标是降低决策与思考成本：阅读正文为中心，一步一个清楚主动作；来源 / 关系 / 字段 / 历史按需展开；常用返回、搜索、添加资料直接可见；不用强制导览、不堆说明卡。

## 3. 沿用的既定标准（不重新决定）

- 企业成员可读本企业全部内外知识；管理员及获产品管理授权成员可编辑、发布、授权。
- 新内容默认对内、AI 关闭；新渠道默认 AI 关闭。
- 生命周期仅三种：草稿 / 已发布 / 已停用。已发布（AI 客服可用）绿色 `#0E7A5F/#EAF4F0/#C2E0D5`；已发布（AI 客服不可用）蓝灰 `#3E4C5E/#EEF2F7/#C9D4E0`，并给原因；不新增大量生命周期状态。
- 搜索"×"只清关键词，保留形式 / 主题 / 状态筛选并回焦点；返回具体实际入口并保留列表筛选，不依赖浏览器历史。
- 线稿图标、折叠动画、Enter/Space、aria-expanded、收起项不可聚焦、reduced-motion、dialog Escape 及焦点恢复全部保留。
- 已有产品 ID、RFQ、推荐与发布历史不因主题设计消失或改写；企业私有原件不因"对外"变成公开下载。
- 旧产品编辑 / 授权路径、第一批已验收界面与数据继续有效。

## 4. 关系模型（主题 - 资料 - 来源 - 版本）

```text
主题（可 0 或 1 个分组；跨分组可互相关联）
 │  介绍段落 / 要点 —— 每条可带来源（指向资料+版本+位置）或标注"人工撰写"
 ├── 关联资料（多对多；一份资料可关联多个主题）
 │      └── 来源与版本：原件登记、识别状态、版本记录（v1…）、更新草稿
 └── 相关主题（主题 ↔ 主题）
```

- 来源设计须记录资料身份、确切版本与位置；资料更新不能让旧主题正文的出处静默指向新版本。人工改写保留来源依据并标注成员修改，不冒充原文引用。这是后续实现要求，本原型未完整实现版本绑定。
- 关联是**独立于内容与权限的关系**：建立/移除关联不改变资料本身、不改变发布状态、不授权 AI。
- 主题正文与资料正文是两类内容：主题正文（介绍/要点）与资料正文（识别初稿/人工撰写）各自保存、各自发布、各自记来源与版本。
- 系统建议内容（建议关联、建议新主题、主题正文初稿）在用户确认前只存在于"检查整理结果"步骤里，**不进入主题导航**。

## 6. 三个主流程

### 6.1 浏览（默认）

全部主题（工作区左列即出现主题 / 文件浏览树：分组 → 主题 → 关联文件；每个主题一个独立折叠按钮，只开合文件列表、不导航、不压返回层，默认收起、展开状态跨阅读 / 返回保持）→ 展开分组 → 主题详情（介绍、要点、出处）→ 展开主题下的文件列表打开原始文件 → 逐层「返回」回到实际进入的路径（从总览树直开文件 → 返回实际总览，不假装曾进入主题正文；从主题树开文件 → 返回原主题、再返回总览；保留筛选）。知识四项入口（全部主题 / 全部资料 / 添加资料 / 问答测试）在左侧主导航（不设工作区顶部功能导航，亦不包含平台其他模块占位）；主题 / 文件浏览树位于工作区内部左列（全部主题总览、主题详情 / 编辑页与由该树打开的资料详情显示——2026-10-12 第九轮修订从总览起即显示，此前「仅主题详情 / 编辑页出现」的规则被替代、历史见 §14；窄屏折叠为内容区「浏览主题」，点选主题或文件后收起，与平台「打开导航」分离），与正文并列、中央为阅读主内容。主题正文的出处是非交互文本（保留文件名称、页码 / 段落、人工出处与不符合对外 AI 条件的标记），不单独作为打开文件的入口；打开原始文件统一从该浏览列的文件列表进入（主题页「关联资料」为非点击资料信息 + 原关联编辑 / 移除 / 添加操作，不再重复文件打开按钮；页内一句轻量提示「从主题浏览列表打开原始文件」，窄屏「浏览主题」说法统一），「全部资料」仍作为跨主题检索入口（指向同一资料、不复制实体，其列表打开资料的方式不变）；重复点击当前主题或当前文件只收起移动抽屉与窄屏浏览树、不新增返回层。主题页按阅读优先渐进展开：正文与要点优先，「关联资料 / 相关主题 / 关系视图 / 版本」默认折叠、标题带数量、按需展开。返回使用轻量内部返回栈（不依赖浏览器历史，不引入路由库），例如：全部资料（带筛选）→ 主题 → 文件 → 返回主题 → 返回，仍然回到带筛选的全部资料。相关主题可互跳；全局图谱不作为首页。空态（无主题 / 无资料 / 搜索无结果 / 未关联主题 / 空主题无关联资料）都给出明确表达或下一步动作。主题总览的列表层级只用局部样式表达（分组标题 18px/600 ＞ 主题名 16px/600 ＞ 说明 13px 常规较浅；主题行相对分组缩进约 20px，320/390 收窄且不横向溢出）——不改列表结构、不新增字段或文案，也不影响「全部资料」列表与主题详情的排版。中央总览的组头是展开 / 收起按钮（默认展开、控制下方主题行；收起时子区不可聚焦；折叠状态记在轻量 UI 状态上，与左侧浏览列相互独立并跨进入主题返回保持；搜索时命中组临时展开、清空后恢复用户原折叠状态，搜索结果不会被折叠藏住；管理模式中的改名 / 删除按钮位于折叠按钮之外、不嵌套）。

### 6.2 统一入库与建议确认

添加资料（第 1 步每次只显示一个资料输入卡片：文件 / 网页地址 / 手动文字，默认文件；卡片下方三个切换按钮，切换不影响已添加列表、工作批次与未保存的编辑，返回第 1 步保持本次选择、仅新添加流程重置默认文件；文件多选只读名称与大小；可载入混合示例）→ 检查整理结果：同一页核对正文（示例初稿可编辑、出处可展开核对、不支持的格式只登记）与确认系统建议的主题（改名 / 合并到已有 / 拒绝 / 追加；可整批设置共同主题再逐件调整；确认前不入导航）→ 发布设置（用途、AI、到期唯一位置；默认对内 + AI 关；对外且开 AI 需一次确认）。

- **不伪造识别**：仅选择文件或粘贴链接不会自动产生识别结果；本原型以明确的"使用示例整理结果（演示）"操作填入示例，图片 / 视频 / 网页保持"仅登记"，真实识别由后端实现。
- 检查整理结果为紧凑列表：每件资料按需展开「检查正文」（标题显示剩余核对数量；默认展开第一件有正文的资料）与「调整主题」（标题带建议摘要）；仅登记资料只保留名称、格式与关联建议，字段始终为折叠选填；核对数量随勾选 / 编辑实时更新，不整页重渲染。
- 发布校验：主题知识正文或文字型资料缺来源、未核对、正文为空、未整理 → 不能发布（列明未通过项并定位）；保存草稿允许不完整；未关联主题只提示不拦截。图片/视频/网页等仅登记原件可完成归档并显示已发布，但明确 AI 不可用，不算发布知识正文；若补充人工正文，正文也必须核对。
- 系统建议的新主题：**同批同名建议合并为一个主题**（单项仍可取消自己的关联）；确认后以草稿建立，不因批次发布变成已发布。**资料核对不等于主题正文核对**：系统整理的主题初稿（显式触发「根据关联资料整理初稿（演示）」）只使用已核对的文字段落与其确切出处，默认「待核对」；成员在主题编辑页逐段勾选「已核对」后才可发布主题；只追加、不覆盖已有内容与人工修改。
- 发布后：列表与详情真实反映结果（草稿→已发布），仍标明"演示内存数据，不代表后台已完成"。

### 6.3 更新资料（版本）

资料详情 → 更新资料 → 新版本对照（旧发布 vs 新整理初稿，标注"文字有变化 / 新增 / 保留人工修改"）→ 保存更新草稿（旧发布版本继续有效）→ 发布新版本（确认后 v 递增，旧版本保留在版本记录）。**保留人工修改不静默覆盖**（对照与优先级规则为设计建议，待评审）。原型演示覆盖一条资料；其余资料更新随实现提供。

## 7. 权限与 AI 证据过滤

- 阅读范围不变：成员可读本企业全部内外知识；编辑/发布/授权沿用管理员与产品管理授权。
- 对外 AI 只用「已发布 + 对外 + 已授权 + 未到期 + 可识别（有已核对正文）+ 来源合格」的内容；读取前与返回前都复核。
- **主题本身也有用途与 AI 开关**（默认对内、AI 关），但主题的对外授权**不能**绕过来源限制：主题中来源为仅内部 / 未授权 / 未核对的段落，即使主题"对外 + AI 开"也不会用于对外回答；主题页明确标注这些段落（原型中"来源为仅内部 / 未授权"标记）。
- 主题关联、生成、分组、移动均不自动授权 AI；仅登记原件的资料即使开启 AI 也不可用（明确原因）。
- 企业私有原件不因"对外知识"变成公开下载；引用只呈现知识名称 / 版本，原件下载仍需企业登录。

## 8. 灵活字段与企业模板的保留方式

- 灵活字段与企业模板**保留为可选辅助功能**，不是主要导航分类。入库流程提供"可选字段（补充信息）"入口：允许定义少量文字 / 数字 + 单位字段，每个字段必须写出来源；不强制选择模板。
- 模板历史 / 版本 / 升级的既定要求（v0.2 第 7 节：模板改版不自动改已有知识、显式升级只改草稿、旧发布快照保留）继续属于第二批设计范围，不因本原型缺页而自动延期；实施拆分待评审，本原型未覆盖模板管理界面（README 如实声明）。
- 旧产品身份（产品 ID、字段核准 / 来源限制、询价与推荐关联）不变；主题与模板都不能放宽既有产品闸门。

## 9. 支持登记不等于识别

- 原型与设计都明确区分：**登记原件**（图片、视频、网页链接、无法识别的文件）与**识别出正文**（文字型文件整理结果、人工撰写正文）。前者不作为主题正文证据、不用于 AI；后者需核对后才发布。
- 本稿**不承诺**所有形式的解析能力：PDF / DOCX 文字识别为设计范围（沿用 v0.2 第一批次）；扫描件 OCR、视频内容理解、网页内容采集均为**待评审的后续候选**，不成为默认承诺。

## 10. 生命周期与 AI 可用分离

- 草稿 / 已发布 / 已停用是唯一生命周期；识别状态（待整理 / 已识别 / 人工正文 / 仅登记 / 未能识别）与 AI 可用性都是**独立维度**，放在状态说明与原因里，不新增主状态。
- 已发布但 AI 不可用一律蓝灰 + 文字原因（未授权 / 仅内部 / 未核对 / 仅登记 / 已到期），不画成故障。**主题与资料在列表和详情使用同一种双标签表达**：「已发布（AI 客服可用）」绿色、「已发布（AI 客服不可用）」蓝灰加原因；草稿与已停用保持生命周期标签，不用绿色暗示可用。

## 11. 原型检查与生产验收分开

- **生产验收（未来开发，不代表现在通过）**：真实文件保存与解析（原件私有、sha256、跨企业不可读）、真实识别与任务恢复、发布持久化、AI 证据过滤的端到端（含读取前与返回前复核）、跨企业隔离、迁移保留。实现阶段另写验收清单（承接 v0.2 D01–D16 的适用项）。
