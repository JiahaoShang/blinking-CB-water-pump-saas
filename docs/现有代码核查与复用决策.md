**核查日期**：2026-10-03
**来源**：`https://github.com/JiahaoShang/blinking-CB-water-pump-saas.git` 的 `main`，核查时提交 `caec80a279dce508ba1c9f73e6e43bb0d181f637`。

## 本次做了什么核查

- 只读检查应用、数据库定义、路由、测试和示例数据；未逐行审计全部代码，也未验证生产部署安全性。
- 在独立的浅克隆中执行 `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest -v`：原有 **24 项测试通过**。这些测试包含与现行需求相反的预期，因此通过不等于 MVP 通过。
- 使用临时 SQLite 数据库启动服务，实际 HTTP 请求 `/login` 和 `/inquiry`：均返回 200；`/inquiry` 跳转到独立买方页面。未据此宣称标准聊天 API 或官网悬浮窗口已经存在。
- 本地文档工作树在导入前没有应用代码；GitHub 测试代码与本地主路径的 Git 进度须合并或保留来源后再推送，不强制覆盖任何一侧。

| 范围 | 已有可复用基础 | 当前 MVP 尚缺或与需求冲突 |

| M1 产品知识 | 产品、来源文件、字段、核准状态及审计表；人工录入和上传入口 | 未实现对所上传资料的可靠抽取与来源定位；发布要求固定字段全部齐全，与“人工核对后可发布有限信息页”冲突；文件用途/许可需核准 |
| M2 详情页 | 公开产品链接和版本快照的基础 | 具体详情页方案尚待评审；获准 CAD/2D/3D 的实际预览或下载、缺项说明及内容版式未通过验收 |
| M3–M4 需求与推荐 | 保存消息、需求修订、规则匹配及推荐快照的基础 | 买方是独立 `/inquiry` 页面，无供企业窗口使用的标准 API；缺少当前确认/待核实/无可靠候选的完整界面及权限验证 |
| M5 问答与人工 | 已核准资料问答、引用和人工任务表的基础 | 资料外问题一提出就创建任务；现行要求是先记录未解问题，买方主动提交请求后才建任务；原会话送达和失败状态需重做验收 |
| M6 RFQ | RFQ 保存、重复提交键、部分销售记录 | 现有代码要求先有已确认需求才收 RFQ，且缺联系信息仍可提交；与“任意阶段可发起、提交时确认联系方式”冲突。买方编辑原 RFQ、卖方修订历史及同会话多采购请求尚缺 |
| M7 销售 | 列表、详情、阶段和备注的基础 | 线索与 RFQ 一对一，未体现同一会话一个负责人及多份 RFQ；共享领取/分配、停止主动联系和完整状态历史需补齐 |

## 复用决定与开发基线

1. 保留现有 Python/SQLite 测试实现作为**待修正的开发基线**，先复用数据对象、演示数据和可运行测试；不因旧计划中的 Next.js/PostgreSQL 建议而立即重写。选择技术起点不代表认可现有安全性或业务行为。
2. 在当前本地 Git 仓库的 `feat/mvp-foundation` 工作树继续开发，逐切片按现行 MVP 文档改正功能和测试。GitHub URL 是目标远端；在明确两边历史及推送策略前，不能把未合并的本地工作说成已上传。
3. 原有 24 项测试保留为回归起点。发生需求冲突时，先新增当前验收测试，再修改旧测试与实现；用真实界面/API 走查证明业务结果。各 M1–M7 模块状态仍以[开发状态与变更记录](开发状态与变更记录.md)的实际证据为准。
4. 首个工程关口是导入该基线、从新的工作目录运行测试与 HTTP 冒烟、补充干净克隆启动说明；随后先做交互走查、数据/API 契约与安全边界，再逐段修复 M1–M7。

**未通过的阶段 1 条件**：目前尚未完成唯一远端历史的安全合并、干净克隆启动和完整“已有/缺失/需修复”逐模块验收。上表是有边界的初查，不是最终代码审计。
