# 开发状态与变更记录

**用途**：区分“文档计划了什么”和“本仓库实际完成了什么”，并记录影响范围的决定。文档不会因代码变化或时间经过自行更新；开发任务结束时应由执行者核对代码、验收结果并更新本页。完整的文字修改历史由 Git 提交保存。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| 未开始 | 当前仓库没有该功能的可验证实现 |
| 开发中 | 已有实现工作，但尚未通过对应验收 |
| 已验证 | 在当前仓库通过对应文档的验收，并留下测试或演示证据 |
| 已上线 | 已部署到明确环境，并确认该环境中的功能可用 |

**限制**：页面原型、外部 Demo、需求文档和代码草稿不等于“已验证”。状态只描述本仓库及指定环境；如果后来发现回归缺陷，应记录新的状态和原因，不静默保留“已验证”。

| 发生的变化 | 应核对和更新 |

| 候选功能正式进入开发 | 从[长期代办](长期功能代办备忘录.md)转入目标阶段需求与验收，并更新其候选状态 |

### MVP 用户旅程与交互评审（截至 2026-10-02 已完成第 1–2、4–7 轮；第 3 轮页面布局待调研）

**来源**：本轮用户提出的体验评审请求；核对当前 MVP 第 1、3、5、6 节及技术架构的数据与隐私边界。本仓库仍只有规划文档，没有可操作产品或真实买家使用证据；下列内容属于设计评审假设，不是测得的流失或效率结果。

**应保留的已有设计**：核准事实与来源引用、可复用产品页、需求可纠正与未知项标记、RFQ 预填、人工任务携带上下文，以及销售集中查看记录。这些要求已经写入 MVP，不因本轮讨论重复新增功能。

**旅程细节的当前状态**（已确认与待评估分别注明）：

- 企业首次使用：已确认资料不完整也可由管理员或获授权成员发布有限信息页；公开内容与缺项须经人工核对确认，后续补齐再发布新版本。抽取失败可手工录入并核准；有限信息页是否进入推荐取决于核准事实的充分度和相关性依据，不取决于页面是否已发布。
- 买家入口：已确认已知型号者可直接查看、提问和询价，无需完整重走需求匹配；页内提问、人工答复及跨页返回已纳入第七轮验收。
- 需求交互：已确认对话结合可编辑参数卡；第二轮确定每次只问最关键的一项，买方可标“不确定”，并在确认已知值和未知标记后选择人工协助或查看待核实候选。具体水泵工程阈值仍由试点企业工程师确认。
- 详情页层级：已确认展示可用且已核准的参数、曲线、图纸、3D 等资料及缺项，但首屏任务、区块顺序和交互布局仍待调研，不能把旧草案中的“参数/曲线/图纸/3D 分区”当成定案。通用分享链接不得包含另一位买家的推荐理由或私人数据。
- 人工接管：已确认只有买方主动提交请求后才创建对外答复任务；MVP 工程师从工作台发布到买方原网页会话。同一浏览器且访问凭据有效时买方可返回查看，也可自愿提供已有联系方式供销售人工回复。未留联系方式时不主动发送站外通知；凭据实现与隐私验收在开发时落实，不虚构回复时限。
- 询价与销售处理：买方可在任意阶段主动发起 RFQ，技术或商务缺项不阻止提交；提交时必须确认可回复联系方式。新 RFQ 进入企业共享队列，由销售领取或管理员分配。买方可在原 RFQ 编辑当前内容，卖方在原线索查看初次提交与逐次变更；不提供买方撤回整份 RFQ 的按钮。买方明确要求停止主动联系后保留记录、暂停主动跟进；联系方式清空及未来经核验的跨设备恢复仍待讨论。MVP 的同浏览器有效凭据边界已确认；服务端保存状态不等于匿名买家可安全恢复会话。
- 采购阶段判断：MVP 第 1.2 节当前将中断且无后续回复标为“正在调研”。建议将可观察的会话中断与尚未知的采购阶段分开；这是待讨论的旧规则调整，当前未改写 MVP。第二轮 RFQ 入口触发规则不等于自动判定买方采购阶段。

**首轮决定与后续进展**：Q1 直接产品页入口、Q2 对话结合可编辑字段已确认并写入 MVP。Q3 已确认普通网页浏览与资料问答不强制留资；人工请求可只在原网页会话查看、无须邮箱/电话，也可选择自愿提供已有联系渠道，提交请求成功才建任务；RFQ 仍必须确认可回复方式。第二轮又确定：买方明确询问其采购价格、交期或样品时仅提示可选 RFQ 入口，不立即强制留资。来自邮件/社媒的已有联系点如何核对仍待试点细化。MVP 当前只有网页买方入口及其他渠道手动来源标签，不因本轮讨论自动增加社媒/邮件消息接入。

**话术设计待验证**：围绕买方原问题说明已知事实、待核实点与可选下一步；使用专业、自然的表达，不隐瞒 AI 身份、不假称人工已介入。英文买方界面文案需由目标买家试读，具体句子不作为当前已验证的成交或信任效果。

**英文买方界面话术草案（占位场景，尚未定稿）**：买方问“这台泵能否用于 50°C 的介质”，且核准资料确实没有覆盖该条件时，可回复：

> Thanks — the liquid temperature matters here. The product information currently available doesn't confirm whether this model is suitable at 50°C. A product engineer can check it against your application. Would you like me to pass along your question and the details you've shared?

按钮可写 `Ask an engineer to review`、`Keep exploring`。买方选择前不写“已安排工程师”；选择后应提供“在此对话查看回复”和自愿填写联系信息的路径，不把填写邮箱/电话设为网页人工请求的前置条件。具体介质、温度、文档覆盖情况须来自该次会话与核准资料，不能把示例中的 50°C 当作任何型号的真实限制。

**第二轮已确认的交互边界**：七轮评审同时核对 MVP 主链路与 V1 对应增量；V1 专有的外部渠道、协作及分析旅程以后单独检查。每轮只问当前最影响匹配的一项缺项；所有匹配产生的候选，包括待核实候选，必须在买方确认已知条件与未知标记后才对其展示。买方不能确认关键条件时，可选择“请求工程师协助选型”或“查看待核实候选”；后者不得暗示适用。多候选并列比较差异；只有经核准的依据才可标排序或最优。已知型号公开页直接访问仍可浏览、提问或发起 RFQ，无须先走选型确认。明确询问其采购的价格、交期或样品时提示可选 RFQ，提交时才强制确认可回复联系信息；一般技术问答、CAD 下载及个案适用性问题不单独触发留资。V1 的邮件/社交渠道须在原渠道完成简短摘要确认/更正，再从原渠道发送可点击详情页链接，具体支持渠道仍待确定。

**第五轮已确认的修正**：上段提到的采购信号提示并非 RFQ 入口的出现条件。买方在任意阶段都可主动发起询价；系统仅记录现有信息和缺项，不能因未完成选型或报价资料不齐拒收。提交后的共享队列由销售领取或管理员分配；自动分配不属于已确认的 MVP 功能。

**第五轮后续决定**：买方提交后可在原 RFQ 中增补、移除及修改字段，并查看当前内容；原始提交与逐次修改仅供卖方查看，原线索提示变化。买方整份撤回按钮已决定不做；RFQ 的留存不能代替对当前购买意向的判断。

**第五轮结束时的联系边界**：买方明确要求不再主动联系时，原 RFQ 留存，销售工作台显示“停止主动联系”且不继续安排主动跟进。买方再次发起沟通可回应其新请求；这不等于默认认定其愿意持续接受主动联系。

**第六轮已确认的发布边界**：授权成员可在缺少曲线、CAD 或部分参数时先发布有限信息详情页；公开内容必须经过人工核对，缺项如实呈现。补齐资料后重新核准、预览和发布新版本；是否能进入推荐另行判断，不能凭“已发布”推断适用。

**第六轮已确认的匹配边界**：有限信息页也按已核准证据分层：足以支持规则的初步推荐、有相关性依据但关键条件缺失时的待核实候选、无技术依据时仅直接浏览页面。任何已知硬冲突不能进入候选；所有匹配候选仍须先经过买方需求摘要确认。

**第七轮已确认的跨页验收**：同一网页会话跨对话、产品详情和 RFQ 页面延续，工况、原问题、人工回复状态与 RFQ 不因页面切换丢失；同一浏览器且访问凭据仍有效时可接续。清除站点数据或换设备后不自动找回匿名会话，卖方已有记录仍按权限保留。此项不提前决定详情页的具体布局。

**本轮余项**：详情页买方信息层级与具体布局继续调研；RFQ 后联系方式清空、会话中断与采购阶段的区别，以及 V1 独有渠道/协作/分析旅程另行评审。已确认结论对应的界面验收见[完整客户旅程与界面验收](完整客户旅程与界面验收.md)，后续决定继续追加历史。
