# 开发状态与变更记录

**用途**：区分“文档计划了什么”和“本仓库实际完成了什么”，并记录影响范围的决定。文档不会因代码变化或时间经过自行更新；开发任务结束时应由执行者核对代码、验收结果并更新本页。完整的文字修改历史由 Git 提交保存。

## 状态定义

| 状态 | 含义 |
| --- | --- |
| 未开始 | 当前仓库没有该功能的可验证实现 |
| 开发中 | 已有实现工作，但尚未通过对应验收 |
| 已验证 | 在当前仓库通过对应文档的验收，并留下测试或演示证据 |
| 已上线 | 已部署到明确环境，并确认该环境中的功能可用 |

**限制**：页面原型、外部 Demo、需求文档和代码草稿不等于“已验证”。状态只描述本仓库及指定环境；如果后来发现回归缺陷，应记录新的状态和原因，不静默保留“已验证”。

## 每次开发任务结束时的最小检查

1. 核对本次功能的需求与验收是否改变；若改变，写明是谁决定、何时决定、影响哪些模块。
2. 核对代码、测试/演示和部署的实际状态，再更新本页。没有证据时保持“开发中”或“未开始”。
3. 如改变了原决定，在相关文档保留变更原因；不要删除历史行。将相关文件纳入 Git 提交，以便追溯逐字差异。
