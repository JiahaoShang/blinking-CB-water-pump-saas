# 企业知识管理 · PRD 与交互设计 v0.2（第二批评审稿）

日期：2026-10-11。**状态：第二批设计范围已确认，详细交互与业务补充规则待评审；没有开始第二批业务代码开发。**

- 已实现基准：[第一批验收记录](企业知识管理-第一批验收记录.md)，544 项完整回归与真实界面走查通过；真实模型 B5 仍待验证。
- 旧设计与 PRD 保留：`design/enterprise-knowledge-prototype/`、`企业知识管理-PRD与交互设计-v0.1.md`。

## 1. 这批想解决什么

第一批让企业可以管理不同类型的知识。但员工还需要手动整理 PDF/Word 正文；产品或服务的信息也缺少适合不同企业的录入表。

第二批把这两件事放到一条流程里：**选择知识模板 → 导入文件或手工填写 → 检查正文和字段 → 保存草稿或发布。**

例如：服务公司上传服务说明，把「响应时间、服务区域、服务方式」整理成可复用的字段；贸易企业整理「材质、尺寸、重量」；企业制度使用「适用部门、生效日期」。不是让所有企业填写水泵参数，也不是让 AI 自动猜出关键数字。

## 2. 方案取舍

| 方案 | 对用户的影响 | 本稿选择 |
| --- | --- | --- |
| 文件自动识别后直接发布 | 操作少，但识别错误和内部内容容易进入客户回答 | 不采用；先核对，再明确发布 |
| 文件正文与灵活字段分别做两套后台 | 功能分散，同一份资料要重复管理 | 不采用；统一知识详情、来源与版本 |
| 文件与模板一起整理，识别结果可编辑 | 有核对步骤，能看清内容从哪里来、是否适合对外 | 推荐；保留第一批三步流程 |

这里的「模板」就是企业自己定义的录入表。例如服务模板里有响应时间，商品模板里有重量；不是一项让用户学习编程的工具。

## 3. 范围与边界

**本批设计包括：**

1. 文字型 PDF、DOCX 的正文与来源位置整理；识别结果人工检查、编辑、收录或排除。
2. 扫描件、加密/损坏文件、旧 DOC 无法识别时的明确提示与人工整理入口。
3. 单文件导入、导入进度记录、失败重试及离开后回来继续；不要求用户守着上传页。
4. 企业知识模板、简单自定义字段、模板版本与已有知识的明确升级。
5. 从识别正文人工选择并填写字段，记录来源；字段核对和客户问答范围控制。
6. 同一知识替换新文件，形成新草稿与版本比较，保留旧发布版本和原件。
7. 已有问答的知识范围、字段范围与版本引用继续有效，不增设新的权限角色。

**本批不纳入：**

- 自动保证表格、合并单元格、图纸、图片、公式、复杂排版完全正确。
- 无需人工确认的自动产品参数推断或自动对外发布。
- 扫描件 OCR 的正式实现承诺：本稿先展示人工整理回退；是否加入本批 OCR 另见第 13 节。
- 网页导入、API/CRM 同步、多 Agent 单独授权、全量 PIM/DAM。
- 复杂嵌套字段、公式计算、跨知识关系表、自动单位换算、批量迁移历史资料。
- 把第一批真实模型 B5 的待验证状态改成已通过；本稿不接真实模型。

**建议初始导入限制：**沿用现有原件 10MB 限制，第二批文字识别另建议最多 200 页；超过时解释限制，允许登记原件并人工整理。数值是评审建议，实际识别能力与运行成本验证后才确定。一次处理一个文件；导入记录可保存多次独立任务，不额外设计复杂批量发布。

## 4. 延续的标准（不重新决定）

- 所有企业成员可读本企业内外知识；管理员和获产品管理授权成员可编辑、发布、授权。
- AI 对外只能用已发布、对外、获授权、未到期、处理成功的内容；产品字段还必须对外、已核准、来源可用。请求结束前再次复核授权和版本。
- 新知识默认对内、AI 关闭；新渠道默认 AI 关闭，开启前核对问答资料。
- 生命周期仍只有草稿、已发布、已停用。已发布（AI客服可用）保留绿色；已发布（AI客服不可用）用中性蓝灰，并显示原因。
- 搜索 X 只清关键词，保留其他筛选；三个分类仍在全部知识折叠菜单里，线稿图标、展开动画及键盘行为保留。
- 全部知识通用新增，产品/服务、文章/FAQ、文件分类各用上下文入口。
- 停用和对外 AI 动作保留必要确认；内部/未授权发布与日常保存不多弹确认。
- 原产品 ID、已发布快照、来源、历史、询价与推荐关联不改写；模板不改变过去的业务事实。

## 5. 页面与导航

不再增加一个独立「文件知识后台」。入口仍是：

```
全部知识
  产品与服务
  文章与 FAQ
  文件资料
```

「问答测试」沿已有入口保留。获管理权限的人在知识页面看到「知识模板」管理入口；模板不是第四种知识分类，普通成员仍可阅读知识但不看到模板管理按钮。

| 页面 | 用户主要动作 | 关键表达 |
| --- | --- | --- |
| 文件资料列表 | 找文件知识、上传文件、查看导入记录 | 知识状态与导入进度分开，已发布仍用双标签 |
| 上传文件 | 选择模板、文件，开始整理 | 说明可识别格式和原件私有；新内容默认对内 |
| 核对内容 | 原文与整理正文对照、填写字段 | 来源位置、待核对提示、已修改标记 |
| 知识详情 | 阅读正文/字段、来源、版本、AI范围 | 显示采用哪个模板版本，不把草稿当线上内容 |
| 更新文件 | 选择新文件、比较、保存新草稿 | 旧发布版本继续使用，确认发布才替换 |
| 知识模板 | 新建模板、定义字段、预览、保存新版 | 用业务语言；说明已有资料不会自动改变 |

## 6. 文件入库交互

### 6.1 选择

上传入口继续三步：1 选择文件 → 2 检查内容 → 3 保存草稿或发布。模板可选「通用文档」或本企业自定义模板；选择通用文档就只整理标题和正文，不强迫所有文档都填产品参数。

选中文件后显示文件名、格式、大小、所选模板及限制。重选覆盖的是未提交选择，不删已经保存的来源。原件仅本企业成员可读，「对外知识」不等于公开原件下载。

### 6.2 整理与返回

导入记录显示业务进度：「正在整理」「待检查」「无法识别」。**这是导入任务进度，不增加知识生命周期状态。**完成识别只创建草稿，绝不自动发布或打开 AI。

生产实现要求刷新/离开后任务和草稿可恢复；原型通过明确的演示场景切换结果，不以倒计时冒充真实处理。

| 情况 | 呈现与操作 |
| --- | --- |
| 文字 PDF / DOCX 有结果 | 进入核对页；段落及来源位置可读 |
| 扫描 PDF 或图片无可提取文字 | 「没有识别到可编辑文字」，提供原件阅读、人工整理正文；不显示已成功解析 |
| 加密文件 | 提示使用未加密文件，保留原件登记选择；不要求聊天中提供密码 |
| 文件损坏或不支持格式 | 说明具体原因，重新选择或人工整理 |
| 处理暂时失败 | 重试同一来源任务，不重复创建知识或发布版本 |
| 超出限制 | 上传前可判断的立即提示；页数在识别后判断，不伪造预检测 |

### 6.3 核对页

桌面左右对照：左边原文及页码/段落位置，右边整理正文与模板字段。手机改为「原文 / 整理内容」切换或上下排列，保留编辑内容和当前位置，不在窄屏塞两列。

正文按段落检查，每段可「收录 / 排除」和「已核对」。文章/FAQ须保留有效正文/问答对；产品/服务可以由有效业务字段构成，但不能正文与字段全部为空。所有收录内容需核对，排除内容不进入发布知识或 AI 候选，原私有文件仍保留。保存草稿允许未核对与缺项。

同一条知识只有一个整体用途。文件里混有内部内容时，排除内部段落或另建内部知识，不暗中增加一套段落权限。核对仅代表员工确认，不能声称系统已证明事实正确。

来源定位要区分：PDF 页码、DOCX 标题/段落位置。DOCX 没有稳定的 PDF 页码，不虚构页号。识别出的表格先可核对呈现；无法可靠保持行列时提示人工整理，不把错位数值自动填字段。

**改了文字会发生什么：**该段「已核对」恢复为待核对，记录人工修改。来源页保留为溯源线索；回答引用的是修改后的已发布知识，不把人工改写当作原文件逐字原文。

### 6.4 保存与发布

- 「保存草稿」可随时保存正文、来源、模板版本与字段。提示尚未完成的核对或必填项，不阻挡保存。
- 「发布」前检查标题、至少一个有效收录段落/业务字段、必填字段、格式、收录内容核对。
- 对外且 AI 已授权时，确认框列出用途、AI使用范围及有效期，用户明确确认；对内或未授权发布不多一步。
- 发布成功只表示内容版本已发布。AI 准备失败仍显示蓝灰「已发布（AI客服不可用）」与处理失败原因，并可重试；不退回旧发布版本偷偷回答。
- 离开有未保存修改时，提供保存草稿、放弃本次未保存改动、继续编辑；取消保持所有内容。不会删除已保存历史或原件。

## 7. 灵活字段与知识模板

### 7.1 模板是什么

公共信息固定保留：标题、知识形态、分类、用途、AI授权、有效期、来源与版本。企业只定义额外的业务字段，不能用模板删除权限、来源或历史。

示例模板是可修改的起点，不是硬编码行业规则：

| 模板示例 | 额外字段示例 |
| --- | --- |
| 服务方案 | 响应时间（数字＋小时）、服务区域（选项）、服务方式（文字） |
| 商品资料 | 材质（文字）、重量（数字＋kg）、支持定制（是/否） |
| 企业制度 | 适用部门（选项）、生效日期（日期）、制度说明（多行文字） |

模板可以关联适用的知识形态；不把所有知识强制改成产品。文章/FAQ原有正文、问答对继续保留，额外字段不替换正文结构。

### 7.2 字段编辑

管理页左边字段列表，右边实时录入表预览。字段设置包括名称、类型、是否必填、填写提示、单位/选项；支持增加、改名、调整顺序、移除。

| 类型 | 交互与验证 |
| --- | --- |
| 单行 / 多行文字 | 正常编辑，允许业务说明 |
| 数字＋单位 | 数字与单位分开；0 是有效值，未填与0不同；不自动换算 |
| 单选 | 配置至少两个不重复选项，空选项不保存；不让 AI 猜选项 |
| 日期 | 选择日期；与知识整体到期时间分开 |
| 是/否 | 明确未选择、是、否；否不是空值 |

名称不能为空，同一模板内不重名。必填只在发布时要求，保存草稿允许缺项；必填并不代表已核准或允许 AI 使用。客户问答可引用的字段另需员工核对与允许范围。

### 7.3 把文件内容整理成字段

选择来源段落 → 选择目标字段 → 人工填写/校对数值与单位 → 保留来源位置 → 确认已核对。

本批不以「自动识别字段」声称模型已正确理解各种行业。预填值必须展示来源并处于待核对；数值和单位不能靠模型猜。人工填写字段显示「人工填写」；改过识别值显示「人工修改」。

每个业务字段展示「允许客户问答引用」和「已核对」。新字段两项默认关闭；外部 AI 候选仍需整条知识已发布、对外、授权、未到期，同时该字段允许且已核对。仅内部字段与未核对字段企业成员仍可阅读，不可用于客户回答。原产品的既有字段审核/来源限制继续使用，不因新模板变松。

### 7.4 模板更新不改旧知识

模板修改保存为新模板版本。新建知识默认用最新版本；已有知识继续使用原模板版本，不自动搬家，不改变已发布快照和历史引用。

- 改名称/提示/排列：同一字段身份保持，旧知识历史仍用原名称和值。
- 已使用字段改类型：作为新字段，说明旧值不会自动转换；避免把「10天」静默变成数字10或日期。
- 移除字段：在新版表单不再显示；旧发布/历史快照保留，不能静默删历史数据。
- 新增必填：只约束采用新版模板后的发布，不把原发布知识突然判成无效。

已有知识的字段页显示「正在使用模板 v1，有新版 v2」，提供「采用新版」入口；编辑草稿同样保留模板版本提示。点「采用新版」先显示新增/移除/类型变化及缺项说明，明确确认后进入核对页，仅更新草稿；发布版本不变，不要求重新上传原件。若已有草稿，以当前草稿为基础保留已填写正文、字段与来源，不能改用旧发布值覆盖草稿；被移除字段的旧值继续保留在历史/草稿保留记录。取消不改任何值。可暂时继续旧模板，不强迫批量升级。

## 8. 替换文件与版本比较

知识详情 →「更新文件」→ 新文件登记为独立来源 → 核对新增/改变内容与字段 → 保存新草稿 → 发布新版。

同一知识 ID 不变，新来源和版本有独立身份与文件校验记录。默认沿用已发布版本的模板、用途和有效期；可明确修改。新知识仍默认对内与AI关闭。已有知识授权的沿用仅是编辑起点：实时撤销、停用、到期继续生效；发布不能凭过期的草稿设置绕过最新限制。

旧 v2 在新文件整理/草稿核对期间继续使用。差异页展示旧值、新值、来源位置与人工修改标记；是文本/字段比较，不声称自动判断新旧资料哪个真实。扫描件无可靠结果时显示未能比较，允许人工核对。

发布 v3 后不再引用 v2；如果 v3 准备失败，该知识暂停用于 AI，而其他知识与渠道不停止。回到历史点「恢复」产生新草稿，不覆盖历史、不直接恢复线上版本。

## 9. AI 使用与员工阅读的关系

员工能读的资料范围保持企业内全量。客户 AI 的范围更小，且在读取前与回答返回前都检查。模板只决定如何录入，不赋予任何权限。

引用应包含知识名称、发布版本、字段/段落、来源文件与可确定的位置。来源限制优先，发布后禁止的文件不能由新草稿换来源绕过。企业原件不对客户公开；对外回答中的来源定位可呈现知识名称/版本，下载仍要企业登录权限。

处理后的文本段落和字段要绑定确切的企业、知识、发布版本、来源与位置；这属于后端设计约束，不把 Chunk/Embedding 等术语放到业务操作页面。真实模型回答质量仍在实际配置后验证，不借本批设计宣称已经完成。

## 10. 状态与细节

- 三种知识状态保持；导入任务和未核对提示放在原因/辅助说明，避免新增五六种主状态。
- 已发布可用绿色、不可用蓝灰，不把未授权描绘成故障；真正的文件失败只在任务原因显示错误。
- 可用性不只看颜色，还要文字、图标和原因；按钮禁用附说明，不让用户猜原因。
- 搜索清空立即刷新并回焦点，其他筛选保留；没有关键词时清空按钮隐藏。
- 发布/确认取消返回原按钮，Escape取消；未保存对话框、移动原文切换不丢已填内容。
- 无管理权限时正文/字段/来源/历史仍可读；没有新增、编辑、模板管理、授权按钮，直接URL/API也必须拒绝越权。

## 11. 验收标准（以后开发用，不代表现在通过）

| 编号 | 操作与预期 |
| --- | --- |
| D01 | 文字PDF与DOCX导入，真实原件、正文与位置一致；核对后真实持久化；无假计时完成 |
| D02 | 扫描/加密/损坏/超限明确原因；人工回退可保存；失败重试不重复建知识 |
| D03 | 排除内部段落，发布正文与AI证据均不含该段；原件仍私有可核对 |
| D04 | 编辑段落或字段重新要求核对；引用标注人工修改且不虚构原文字句 |
| D05 | 保存缺项草稿成功；未完成核对/必填/空内容发布失败并定位问题 |
| D06 | 新知识对内AI关闭；已发布未授权为蓝灰，对外授权发布必须明确确认 |
| D07 | 新文件保存草稿时旧发布仍在；发布后只用新版，失败不暗中回用旧版 |
| D08 | 新模板定义字段并实时预览；重名、空选项等不保存；0与否正确持久化 |
| D09 | 文件段落填写字段，值、单位、出处可追溯；仅内部/未核准字段不对外回答 |
| D10 | 模板v2不改既有知识v1；明确升级只改草稿；移除/改类型不抹掉旧快照 |
| D11 | 询价与推荐保持原产品ID与历史事实，不因模板或文件更新改变过去记录 |
| D12 | 跨企业任务、模板、知识、来源、下载不可访问；普通成员只能读不能写 |
| D13 | 检索前与模型返回前撤销/到期/来源禁用均立即生效 |
| D14 | 搜索清空保留筛选；三分类折叠动画、键盘、焦点与320/390手机可用 |
| D15 | 刷新、离开、重启后任务与草稿仍在；真实处理失败有原因和可恢复路径 |
| D16 | 原型演示不计D01等后端验收，模型真实联调独立记录未验证/通过 |

本轮设计验证只检查可点击操作、文案、布局和规则呈现；发布/解析/模板数据持久化等生产验收需要后续代码与真实样本。

## 12. 本批技术方案的约束（不是开发计划）

继续现有模块化单体与知识统一入口，不为模板另建产品后台。既有知识版本作为发布事实；新来源、导入任务、模板定义/版本和字段身份需要可追踪。识别处理不能长时间阻塞请求，要有任务记录和失败恢复；是否用现有进程后台处理或新工作进程留到技术计划评估。

解析器、OCR供应商、任务运行方式、页数上限、文件预览方式尚未选型，不安装依赖、不改架构决策状态。原件权限、文件路径与下载校验复用第一批，使用真实文件样本再决定细节。

## 13. 尚需评审的业务补充规则

范围已确认，下面规则目前是建议；评审稿可先完整演示，不静默当作批准实现。

| 编号 | 本稿建议 | 影响 |
| --- | --- | --- |
| P2-01 | 本批先正式支持文字PDF/DOCX；扫描件人工回退，OCR另评估 | 如扫描件占多数，应提前讨论OCR成本与核对体验 |
| P2-02 | 管理模板也沿用管理员/产品管理授权 | 是否需要仅管理员改模板，取决于企业协作方式；不影响所有成员阅读 |
| P2-03 | 已有知识可继续旧模板，升级需人工确认 | 保持历史稳定；不会一次改模板就强制所有人补资料 |
| P2-04 | 一份混合文件可排除内部段落，剩余作为对外知识；内部内容另建知识 | 不新增复杂段落权限，但需员工明确检查删减 |
| P2-05 | 初始10MB/200页、单文件处理，超过可登记原件人工整理 | 识别性能和资源消耗需要真实样本验证，200页未定为硬承诺 |

评审后把确认项写回当前要求与变更记录，再编写技术架构/开发计划并由Hermes执行。本轮只交付设计，详细实施计划尚未编写；业务补充规则在设计评审时集中处理，不拆成反复弹出的开发确认。

## 14. 设计稿演示边界

原型重点覆盖文件＋模板的连贯操作、只读视角和版本变化。原文是可定位的示例文字，不是实际PDF/DOCX渲染；文件选择不读取内容；解析失败、发布后失败通过明确演示控件切换；浏览器刷新即重置。

生产级数值/日期格式验证、纯字段产品的完整录入路径、真实超限/加密文件检测、任务恢复、多人同时编辑及真实模型能力以第11节开发验收为准，不由原型前端状态证明。
