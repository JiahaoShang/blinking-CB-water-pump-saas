# 企业知识管理第一批技术方案与开发计划

日期：2026-10-10。状态（2026-10-11）：第一批任务 1–4 已实现，独立完整回归 544 项及真实界面验收通过；真实模型联调 B5 按用户决定待验证。最终完整回归、真实界面证据及提交以《企业知识管理-第一批验收记录》为准。

## Goal
完成 PRD 第 8 节第一批的真实存储、管理、授权与客户视角问答测试流程，不把静态原型当实现。

## Architecture
沿用 Python 模块化单体和 SQLite。通用知识逻辑放独立模块，HTTP 页面及接口经现有身份认证接入；所有读取、写入和客户检索携带企业 ID。保留既有 products、product_versions、sources 及推荐、询价关系，用关联适配复用原产品 ID，禁止删除重建产品。生命周期与处理结果分开存储。

## Tech Stack
Python 标准库、SQLite、现有服务端 HTML 与原生 JavaScript/CSS；模型使用已有企业模型服务边界，不增设新服务。文件存储复用既有私有目录约束。

## Spec
依据 docs/企业知识管理-PRD与交互设计-v0.1.md、design/enterprise-knowledge-prototype 最终版及本轮明确确认。第一批包括文章、FAQ、产品/服务、TXT/MD/CSV导入、来源版本、授权生命周期、全文搜索筛选、客户问答测试。PDF/Word只登记原件并人工整理正文，不自动解析。

## Global Constraints
- 所有企业成员可读本企业内外知识；管理员和获产品管理权限成员可编辑、发布、授权。服务端强制执行，禁跨企业。
- 可选到期时间，留空长期有效；过期、停用、撤销授权在检索前排除。
- AI只引用已发布、对外、已授权、当前处理完成的资料；产品逐字段再校验对外、核准、来源限制。
- 新渠道默认AI关闭，开启资料确认保留；后端组件名称不变成业务按钮。
- 可用标签原绿色，不可用中性蓝灰；搜索只清关键词，分类对应新增；折叠导航保留动画、线稿图标、aria及键盘和减少动画偏好。
- 不访问密钥，不改变真实演示数据；验证在临时数据库，外部模型测试按实际配置能力报告。
- Hermes执行业务代码，先写有意义失败测试再实现；Codex独立验收。无真实模型时明确显示未连接，不生成预置假答案，不把这一项标为通过。

## Review Focus
企业隔离、字段泄漏、版本引用一致性、停用与过期立即排除、原产品关联保留、实际上传后刷新与重启持久化、无权限接口拒绝、原型与产品边界。

## 最小数据契约
knowledge_items保存企业、形态、关联原产品ID、生命周期、当前发布版本、草稿引用、负责人；knowledge_versions保存不可变正文/FAQ/字段快照、分类、用途、授权、可选到期、作者与来源；knowledge_sources保存私有原件或手工出处；处理结果绑定确切版本并记录错误与重试。来源与主题分类分别管理，不把分类决定成编辑器类型。具体SQL可依据现有库减少重复表，但这些业务约束不可省略。

## 任务1：真实存储、生命周期与权限
文件：新增通用知识模块及test_enterprise_knowledge.py；app.py只增加必要初始化及接口接入。
先写临时SQLite测试：跨企业不可见、无products权限拒绝写但可读、发布编辑草稿不改变线上版本、恢复创建草稿、停用/授权/到期即时筛除；记录失败，再最小实现。更新发布后旧版本不得继续用于这条回答；准备成功绑定新版，不能靠计时模拟。验证重开数据库仍有内容和历史。

## 任务2：导入、产品适配与版本来源（已实现：导入模块、产品只读投影、精确到期时间与边界测试；见开发状态记录）
复用原产品ID/字段/来源/历史；对外按已核准字段过滤。TXT/MD/CSV真实保存原件，解析后用户核对、保存草稿/发布；CSV作为文本材料，不能自动推断行业字段。验证实际文件字节、私有下载权限、空正文拒绝发布、FAQ完整、恶意HTML安全转义、文件上限与格式错误。既有产品推荐/询价关联回归。

## 任务3：管理界面（已实现：enterprise_knowledge_ui.py + 折叠导航；问答测试页按任务4处理，本任务未建模拟问答）
文件：独立知识页面模块/静态资源，business_channel_ui.py route分派、app.py必要导航适配。沿最终原型完成统一列表、详情、编辑、导入3步、属性栏、来源版本、未保存保护、只读体验。保留旧产品路径可用，新统一入口不破坏旧编辑/核准业务。分类可直接录入主题，不建设完整字段设计器。默认折叠，搜索清空不丢筛选，移动端390宽与键盘实际走查。只从真实后端数据渲染，无演示管理员切换、预设问答或假处理计时。

## 任务4：客户视角真实问答及处理（已实现：answer_knowledge_question、问答测试页、网页/渠道共用阶段；清单8-14 复核修正后追加原产品快照投影与侧车 AI 授权/到期闸门；真实模型联调待验证）
复用现有模型服务入口，先在本地校验可用版本和字段后提供候选证据，回答必须绑定真实名称和版本。处理应有实际构建/索引结果、失败重试，远程响应后再检查当前版本与授权防并发撤销。无依据提示建议转人工，按现有买方主动申请人工协助规则，不自动创建无人联系任务。测试页的建议转人工是提示；真实渠道继续既有接续流程，不扩展自动派单。模型未接通显示明确限制，保持该项未验收。共用过滤器覆盖网页和已开启的渠道调用，不能只在测试页生效。

## 验证与交付
- 针对性：python3 -m unittest test_enterprise_knowledge -v（按实际文件名调整）。
- 回归：python3 -m unittest discover（记录实际通过数和失败，不能复述旧416条结果）。
- 实际浏览器：隔离测试服务登录→文章/FAQ创建→发布→搜索清空→详情/版本→上传→刷新；无权限只读、390宽、折叠菜单键盘与动画；截图与测试数据路径记录。
- 模型测试：真实可配置模型有条件则实测引用/不足转人工；仅本地fake HTTP集成测试不得叫真实模型通过。
- 同步PRD、设计README/REVIEW和开发状态：区分设计基准、已实现、未验证；保存开发授权及P2/P3确认历史，不覆盖旧理由。
- 完整已验证切片提交，未完成不包装完成；交付改动文件、检查结果、剩余问题、文档位置、提交号。

## 常规实现决定
旧产品路径保留；问答测试仍在知识模块；筛选沿用途和AI可用性；历史恢复新草稿；新版准备阻断仅本条；原型丢弃策略沿未保存保护不增加独立删除能力。后续批次不排期。两项业务未定P2/P3已由用户本轮回答确认，无需重复授权。
