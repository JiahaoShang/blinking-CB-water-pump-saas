## 使用流程与验收

- 管理概览不再呈现模型接入。左下角账号头像打开菜单，设置入口带线稿图标。
- 所有已登录成员可查看设置中的服务状态；只有企业管理员能连接、替换、断开企业 API。既有「企业设置」业务规则保留。
- 无企业覆盖配置时，业务使用部署方提供的平台模型服务，企业用户无需填写密钥。
- 自定义接口支持公网 HTTPS OpenAI Chat Completions 兼容协议及 JSON 输出；模型供应商专有协议不在本次范围内。填写基础地址、模型名称、密钥，先执行一次小型需求提取测试，成功后原子替换企业配置。
- 新配置测试失败时保留原配置。自定义模型出错不自动调用平台模型；主动断开后后续请求恢复平台服务，无需重启。
- 官网 API 以网站所属企业选服务，渠道以连接所属企业选服务；不依赖后台操作者的企业身份。核准事实、对外知识权限和人工协助边界保持不变，Dify 共享生成仍未开启。
- 管理员可展开运行诊断，保留原有最近调用状态、用量等信息；不显示密钥。

## 部署与密钥

平台基础模型仍由部署方按 README 配置 `AI_MODE=deepseek`、`DEEPSEEK_API_KEY` 等；企业用户无需进行此操作。本地未配置真实平台模型时界面明确说明规则模式，不能算真实模型服务验收通过。

企业覆盖配置保存在 `<数据库路径>.model-secrets/`，目录权限 700、文件权限 600，以企业标识的哈希命名；不是加密存储，须由部署方保护主机账号及备份。密钥不进入 SQLite、审计、Git 或页面。备份恢复须同时安全恢复该私有目录；无法读取覆盖配置时禁止悄悄改用平台 API。

自定义请求检查公网地址，按本次解析出的公网 IP 连接并验证原域名 TLS 证书；不跟随重定向、不读取系统代理，避免密钥被转发至其他地址或访问内网。使用自定义接口的主机须可直连供应商 HTTPS 服务。

## 2026-10-13 官方通道固定参数：思考开启·强度 low（用户明确）

- 用户明确（纠正此前理解）：推理强度为 `low`，不是关闭思考。官方通道（平台 DeepSeek 与企业自定义指向官方 `api.deepseek.com`）请求固定 `model=deepseek-flash`、`thinking={"type":"enabled"}`、`reasoning_effort="low"`；依据官方文档 Thinking Mode 与 Chat Completions：`low` 受支持，思考默认开启、默认档为 `high`。历史纠正：此前实现为「显式关闭思考模式」（`thinking disabled`，自 `8368d0a` 起），该写法按本轮用户要求废止。
- 不可切换：环境变量（`DEEPSEEK_MODEL`）、直接构造、运行期修改与旧企业配置都不能把官方通道切到其他模型或关闭/调整思考；设置页运行诊断与 `ai_call_log` 的模型字段与实际请求一致（均 `deepseek-flash`）。
- 配置规范化：旧官方配置（如存有 `deepseek-chat`）读取时按 `deepseek-flash` 规范化，不改写原文件、不动密钥；新保存的官方配置持久保存为 `deepseek-flash`；连接表单占位符同步为 `deepseek-flash`。企业自定义指向其他第三方兼容端点时保留原协议，不注入 DeepSeek 专用字段。
- 输出边界：仍只读取响应最终 `content`（思考模式的 `reasoning_content` 不进入页面、日志、答案或后续请求）；`finish_reason=length` 等非正常结束按输出不可用（可重试）处理，不当作成功答案；单次输出上限沿用 512 tokens 未调整。
- 验证（隔离副本，无真实模型调用）：`test_ai_deepseek.py` 与 `test_model_settings.py` 的新增/更新用例修复前 7 项按预期失败（red，35 项中），修复后 35 项全部通过（green，退出码 0）。真实账户下 `low` 强度的实际延迟与输出（含 512 上限是否截断）未在本轮验证。
