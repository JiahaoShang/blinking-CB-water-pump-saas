# 试点就绪核对表（对外试点前的逐项检查单）

**性质**：本表是「从小范围试点走向真实对外开放」的门槛清单。每一行 = 一项检查：**现在能机器验证的已经用演示数据干跑并留档；剩下需要外部条件的，写清"要谁提供什么、到手后跑什么、什么算通过、谁签字"**。试点前逐行打勾，全部通过才可对外。
**干跑记录**：2026-10-03 在本机演示环境执行，原始输出见 `data/evidence/pilot-readiness-2026-10-03/`。干跑 = 脚本本身已被证明可运行；**不等于**该项已在真实条件上完成。
**通用前提**：本机 Python 标准库即可运行全部脚本（无需第三方依赖）；命令均在仓库根目录执行。

**2026-10-04 资源现状（用户直接说明，尚未完成试点验收）**：项目负责人有可用于部署的自有域名和 DeepSeek 模型服务账号；目前只有展示用 Demo 资料，没有可参加核准和签署的厂方工程师或销售人员，实际工作由项目负责人一人承担。域名可用不等于正式站点、HTTPS、托管备份或跨域配置已经部署；拥有模型账号不等于已取得接口凭据并完成真实故障联调。Demo 资料只能用于内部演示，不能代替本表第 1、4、7 项所需的厂方授权、工程核准与销售角色验收。后续若先做单人内部彩排，应单独记录为内部彩排，不勾选真实角色签署项。

## 二、脚本清单与用法

| 脚本 | 用途 | 依赖 |
| --- | --- | --- |
| `tools/pilot_checks/check_public_permissions.py` | 公开文件 ↔ 许可记录/哈希/厂方清单 一致性 | 试点库、厂方清单（选填，试点必填） |
| `tools/pilot_checks/check_cors.py` | 跨域白名单放行/拒绝行为 | 运行中的服务 + 网站标识 |
| `tools/pilot_checks/restore_drill.py` | 备份→恢复→计数对照（含耗时） | 试点库、uploads 目录 |
| `tools/pilot_checks/generate_threshold_review.py` | 生成工程师核准单（产品事实 + 样例工况判定） | 试点库 |
| `tools/pilot_checks/check_db_migrations.py` | 旧库迁移后结构/索引核查（不改原库） | 任意数据库副本 |

所有脚本 `--help` 均自带用法说明；脚本行为由 `test_pilot_checks.py`（4 项测试）锁定，跑全量测试即可一并验证。
