## 2. 数据模型（侧车表，`init_knowledge_phase2` 幂等建表）

- `kb2_groups`：可选自定义分组（删除分组只把主题置为未分组，主题与关联保留）。
- `kb2_topics` / `kb2_topic_versions`：主题身份 + 正文版本（草稿/已发布/superseded 历史）；正文段落逐段保存来源钉住（`source={kind:knowledge|product,...,version_id,source_id,location}`），人工撰写明确标注，不冒充原文。
- `kb2_topic_relations`：主题 ↔ 资料多对多；关联时钉住 `pinned_version_id/pinned_source_id/pinned_version_number`；产品只读适配（不复制产品行）。
- `kb2_batches` / `kb2_sources` / `kb2_paragraphs`：入库任务、私有原件（token 命名 `kb2-{32hex}.ext` + sha256）、逐段整理（位置 JSON、origin/edited/checked/excluded）。
- `kb2_source_fields`：字段来源（可钉住具体段落→真实 source/version/location；0 与「否」为有效值）。
- `kb2_topic_suggestions`：建议（pending→confirmed / rejected；改名、合并、整批共同主题、逐件调整；确认前不建立主题）。

任务状态（批次/来源）与知识生命周期（knowledge_items 草稿/已发布/已停用）分开存储；数据库是唯一事实来源。

## 4. 已落地并验证的关键行为（每条都有测试对应）

1. **真实解析**：TXT/MD/CSV 行号；文字 PDF 按 **真实页码**；DOCX 按段落（含标题路径与被标记的标题段）与**表格行列**，不虚构页号。
2. **明确失败、不谎报**：扫描型 PDF→「仅登记」（提示无可提取文字）；加密/损坏 PDF、损坏 DOCX、解压炸弹（高压缩比 ZIP）、未知格式→失败并给原因；旧 DOC/图片/视频→仅登记并提示人工整理。
3. **资源保护**：文本 1MiB / 文档 10MiB 在创建批次时拒绝；文字 PDF 200 页处理上限（超出仍可原件归档/人工整理）；DOCX 解压前检查（总解压 >64MiB、单条目 >32MiB、压缩比 ≥200 且 >8MiB 均拒绝）；DOCX 段落 5000 段截断并警告。
4. **统一入库**：多文件 + 链接（只登记、不抓取）+ 手动文字混合批次；**完成识别只创建草稿，绝不自动发布**；链接/图片等仅登记原件同样建有资料草稿（条目仍是草稿）。
5. **持久与恢复**：批次/来源/段落/条目全部落库；崩溃（BaseException 模拟）后来源停在 processing，`kb2_process_pending_sources` 从数据库继续且**不重复创建条目**；失败重试幂等（成功后不可再重试；已有人工修改的来源拒绝自动重建）。
6. **核对 / 编辑 / 排除**：勾选核对；编辑文字→撤销该段核对并记「人工修改」；排除段不进入正文（发布正文与草稿正文都不含）；已发布资料编辑/补人工正文转新草稿，线上不变。
7. **发布闸门与幂等**：文字型资料必须**全部收录段落已核对**（错误定位到段号）、拒绝空正文；重复发布幂等（返回 skipped，不产生重复版本）；"保存设置"允许未核对的不完整草稿。
8. **仅登记原件归档**：无正文来源走专门归档路径（内容标记 `kb2_registered_only`），显示为已发布但 **AI 结构上不可用、不算发布知识正文**；补人工正文后必须核对才能发布。常规正文不经过该路径——第一批「空正文不能发布」闸门未改动。
9. **主题建议与确认**：系统建议只来自**真实文字命中**（现有主题名出现在资料正文里）；新主题建议来自成员输入（整批共同主题 = 全选来源），不凭文件名猜测；改名/合并/拒绝/逐件调整均支持，**确认前不建立任何主题**；同批同名合并为一个；确认幂等；被拒绝的建议不会被自动复活。
10. **来源钉住**：主题段落与关联都钉住资料确切版本；资料发布新版后旧主题出处仍指向原版本并标记「来源资料已更新」（不静默换版）。
11. **安全与隔离**：跨企业读/写/关联/批次/段落/原件全部拒绝；无 products 授权的成员可读不可写（撤权立即生效）；原件私有 token 命名（不含原始文件名路径）、sha256 校验、仅本企业可读。
12. **兼容**：旧产品/文章/FAQ 全部出现在 `kb2_list_materials` 且**未自动分配主题**；发布/授权/处理复用第一批协议（`list_customer_qa_evidence` 等未改动且不受影响）。

## B2-B01 修复补记（Hermes，2026-10-12）

- 来源：修复上节 Codex 复现的并发重复创建阻断；上节复现理由、脚本与原始判定原样保留（本补记不改写、不覆盖），只记录修复实现、接口变化与修复证据。
- 根因（与原复现一致）：同一来源的同步处理入口与 worker 扫描入口可并发进入；处理前没有原子认领，条目身份按各自读取到的 `item_id=None` 各生成一次。
- 修复（实现在代码与数据层，非文档约定；范围限定单服务器多连接，不扩分布式）：

>  1) **原子独占认领**：`kb2_sources` 新增 `processing_owner`（`主机:进程:线程:随机`）与 `processing_lease_until`（epoch 秒；默认租约 600s，`KB2_PROCESSING_LEASE_SECONDS`；旧库经 `init_knowledge_phase2` 幂等迁移补齐）。认领 = 条件 UPDATE（pending→processing；processing 仅在属主失活或租约过期时可接管，接管条件带旧属主/旧租约防覆盖）；同进程多连接另有模块级活动认领表互斥（按数据库真实路径），活动 processing 不被另一线程抢执行；处理收尾写入带认领校验，认领被接管则回滚丢弃。
>  2) **安全崩溃恢复**：processing 状态与认领先提交再解析；BaseException 中断后同进程恢复入口立即接管（原执行线程已终止），跨进程按属主进程退出 / 租约过期接管；已成功来源不能再重试（幂等）。
>  3) **来源→条目唯一身份**：`item_id` / `knowledge_source_id` 条件写入（`... AND item_id IS NULL`）；竞争失败方复用数据层已写入的 ID，不重复创建条目。
>  4) **排队入口（不阻塞请求）**：`kb2_create_batch(..., process_now=False)` 只落库、立即返回 `batch_id`，由入库线程独占认领后真实处理；默认 `True` 保持原 CLI/测试同步行为。批次创建与处理收尾补齐审计提交——排队/worker 路径不再遗留未提交写事务（写锁）。
>  5) **重试入口**：`kb2_retry_source` 对活动中的来源明确拒绝（不抢占、不重复解析）。
