## 0. 三分钟看懂（给第一次接触这个项目的人）

**我们要解决什么问题？**
目前产品资料已有核准、发布、来源和版本能力，但文章、政策、FAQ 等知识还没有统一管理入口。重构需要把这些能力扩展到不同知识形态，并让使用者清楚知道每条资料是否允许、是否已经准备好用于客户问答。

**这次设计怎么解决？**
把企业知识做成**一个统一入口**：文章、FAQ、产品、服务、文件资料都放在这里管理。每条知识有自己的**生命周期**（草稿 / 已发布 / 已停用）、自己的**用途**（对内 / 对外）、自己的**授权**（是否允许 AI 客服使用），而「AI 客服能不能用这条来回答客户」由系统按规则**自动算出来**，不需要人去手动挑状态。

**为什么这样设计（三条理由）：**
1. 客户能不能被正确回答，取决于内容、授权和有效版本共同满足要求，所以由系统判断可用性，用户不用再手选一个“就绪状态”；
2. 企业里「对内资料」和「对外资料」性质不同：内部资料（比如培训、成本口径）永远不能拿去回答客户，所以用途和授权必须分开表达；
3. 今天发布的版本要能被明天的新版本替换，但替换过程中不能让 AI 拿着旧价格、旧政策回答——所以更新要有草稿机制和「准备中」过渡。

**本次两条硬性修改（用户已确认，必须贯穿）：**
- 生命周期只保留三种：**草稿 / 已发布 / 已停用**。已发布统一显示一个状态：**「已发布（AI客服可用）」或「已发布（AI客服不可用）」**；不可用的原因（仅内部、未授权、准备中、处理失败、过期）只作为详情里的**辅助提示**，不是额外状态。
- 四个概念各有分工、界面不重复：**状态**说明资料走到哪一步；**使用范围**说明对内还是对外；**允许AI客服使用**是一项授权设置；**AI客服可用**是系统计算的结果。

## 2. 背景：现状与差距

**现状（以当前代码实际可见的范围为准）：**
- 现有「企业知识」页面以**产品为中心**：每个产品下展示知识字段表（内容、使用范围、核准状态）、来源资料列表（可阅读原始资料）、以及一行「AI 资料状态」摘要。
- 渠道账号页已有指引：AI 只使用已核准、获准对外问答的知识；开启 AI 接待前有确认对话框。
- **基础平台真实模型仍未接通**：当前不存在可以宣称"已实现"的通用问答能力。本设计不把任何未接通能力写成已具备。

**主要差距（本次要设计补齐的）：**
1. 知识只有"产品字段"一种形态——没有文章、FAQ、服务政策、企业文化、培训等载体；
2. 产品模块已有核准、发布、撤回和版本历史；尚未扩展成所有知识形态共用的草稿、发布、停用流程；
3. 产品字段已有内外范围及核准规则；缺少通用文章/FAQ 的逐条 AI 授权及可用性呈现；
4. 产品模块已有检索和编辑能力；企业知识汇总页尚未形成独立的通用知识搜索、编辑与版本工作区；
5. 产品来源已有上传、登记和文本/CSV 候选提取流程；尚未形成通用文章内容的导入、核对、发布闭环，PDF/Word 自动解析仍未实现；
6. 「就绪」与「授权」语义混杂，容易出现"管理员以为能用、客户实际得不到"的情况。

## 3. 用户目标

| 角色 | 想完成的事 | 判断"做对了"的标准 |
| --- | --- | --- |
| 知识整理者（运营/市场/文员） | 把政策、FAQ、产品介绍整理进来并发布 | 发布后知道自己"这条能不能被 AI 用" |
| 管理者（有编辑/授权权限者） | 控制哪些内容允许对客户开放 | 授权/停用能立即生效 |
| 销售/客服 | 查资料、找最新版本、把客户问题转人工 | 看到的是"当前有效版本" |
| 客户（模拟视角） | 得到有依据的回答 | 回答有引用；没依据就说转人工 |

## 4. 模块定位【建议】

- 一个**统一的企业知识入口**：「全部知识 / 产品与服务 / 文章与FAQ / 文件资料」四个视图 + 「模拟客户问答」测试入口；
- **分类只做筛选**，不另设一个巨大的"知识维护中心"；
- 现有「企业知识」与「产品」两个全局入口**合并为一个**是建议；评估后若采纳，**旧的产品路径保留兼容**（旧链接跳转不 404，具体实现方式待评审）。

## 5. 本次两条修改（详述）【本次修改】

### 5.1 修改 A：生命周期只保留三种

| 生命周期状态 | 含义 | 展示规则 |
| --- | --- | --- |
| 草稿 | 还没发布；不参与任何问答 | 列表中显示「草稿」；「需要核对」是草稿的辅助提醒（不是状态） |
| 已发布 | 已上线；是否可以给 AI 用由系统计算 | **统一显示**：「已发布（AI客服可用）」或「已发布（AI客服不可用）」+ 类型标签（文章/FAQ/产品/服务/文件资料）；两种标签**按可用性区分配色**：**可用＝绿色**、**不可用＝中性蓝灰**（对比度足够，文案与颜色共同区分）——不把"AI 不可用"染成黄/绿告警色，避免内部正常资料像出故障；不可用原因仍以辅助提示另行说明 |
| 已停用 | 已停止使用；可重新启用 | 显示「已停用」；历史版本、来源、关联对象保留 |

明确不做的事：不把"AI 准备中 / 处理失败 / 待核对"做成第四个主状态；不引导用户手选"就绪状态"。

### 5.2 修改 B：四个概念语义分离，界面各自只出现一次

| 概念 | 回答的问题 | 谁决定 | 界面上出现在哪 |
| --- | --- | --- | --- |
| 状态 | 资料走到哪一步（草稿/已发布/已停用） | 人的动作（保存/发布/停用） | 列表一处；详情标题处一处（同一枚状态标签） |
| 使用范围 | 这条资料对内还是对外 | 人在编辑时设置 | 属性栏（分类 / 用途 / AI授权 / 关联对象） |
| 允许AI客服使用 | 是否授权 AI 引用它 | 授权设置，可随时开关、立即生效 | 属性栏的开关 |
| AI客服可用 | 系统算出的最终结果 | **系统计算**，人不手选 | 由「已发布（AI客服可用/不可用）」文案承载；不可用原因作为详情辅助提示 |

属性栏**只放**：分类、用途、AI授权、关联对象——不重复显示生命周期。

## 6. 规则清单与决策来源

**以下段落为原评审阶段的确认状态；2026-10-10 用户已授权第一批，第一批内规则按本稿及本轮补充确认执行，后续批次仍不自动排期。**

R1、R3、R4、R21 沿用用户此前明确的企业知识及后端隐藏原则；R6 的已发布双标签表达来自本次明确评论。其余是评审稿提出或延续现有产品约束的设计要求，不代表用户已经确认全部实现细节。尤其 R10 的新版准备期间暂停该条知识、R13 的历史恢复方式、R16 的确认策略，以及首批导入范围仍待评审。用户对重复展示的评论由 R7 的布局建议回应，并非新增一项已经确认的业务权限规则。

- R1 每个企业的资料独立归属；本企业所有账户**默认可读**内部及外部知识。
- R2 本企业所有成员可阅读；管理员及获产品管理（products）权限的成员可编辑、发布和设置 AI 授权。来源：2026-10-10 用户对 P2 的明确答复；原待评审状态保留于后文决策历史。
- R3 AI 客服**只使用已授权的对外知识**；对外知识 ≠ 公开原文件下载（原文件默认不公开）。
- R4 新外部渠道连接 AI **默认关闭**；启用前必须确认资料（沿现有渠道流程的确认方式）。
- R5 保留原有产品 ID、核准字段、来源、历史版本、推荐/询价关联；**不把水泵字段硬编码为通用知识字段**。
- R6 生命周期仅：草稿 / 已发布 / 已停用（修改 A）。
- R7 四个概念语义分离、界面不重复（修改 B）。
- R8 「AI客服可用」= 已发布 + 对外 + 已授权 + 有效（未过期） + 当前版本准备完成；**系统计算，用户不可手选**。
- R9 内部资料**即使管理员测试也不用于模拟客户回答**。
- R10 编辑已发布 v1 时产生草稿；发布前 v1 仍可用。发布 v2 后、v2 处理完成前，**该条知识**标记「已发布（AI客服不可用）」；只影响此条，渠道不停机。
- R11 修改授权 / 停用**立即生效**（在检索前生效），不能等远程索引删除。
- R12 失败可重试；主状态仍为「已发布」（不可用原因：处理失败）。
- R13 历史恢复**创建新草稿**，不覆盖历史版本。
- R14 产品/服务的对外与内部字段并存时**按字段过滤**：不能因为条目对外就暴露整条内部字段；AI 只引用「对外且已核准」的字段。
- R15 混合内容的文件不承诺自动分出对内/对外；需人工整理出可授权内容；原文件默认不公开。
- R16 必要确认仅两处：**停用**与**对外AI发布**（对外且授权的发布、重新启用、开启授权）。日常保存不反复弹窗。
- R17 无权限者：隐藏编辑操作并说明只读；**原型不宣称验证了后端隔离**。
- R18 文件导入 3 步：选文件 → 检查识别内容（可编辑标题/正文/分类/用途）→ 保存草稿或发布。
- R19 导入能力现状：当前项目仅有文本/CSV 候选字段提取（第一批可用）；PDF/Word 自动解析为**后续批次**并明确说明；原型不实现虚假的 PDF 自动识别。
- R20 问答测试显示：模拟答复 + **资料名称/版本引用**；资料不足 → 提示转人工；不承诺模型自报置信度。
- R21 AI 技术自动处理对用户隐藏；后端服务名（如 Dify / LangBot）不作为业务操作名称出现。
- R22 检索范围受企业、有效版本、字段/条目授权限制；普通全文搜索与 AI 问答的差别必须写明。

## 8. 范围：第一批 / 后续批次

**第一批（本次设计覆盖）：**
- 手动创建与编辑：知识文章（含 FAQ 问答对）、产品/服务（含结构化字段）；
- 文件导入：**TXT / Markdown / CSV** 本地文本读取 + 原件登记 + 人工核对 + 保存草稿/发布；
- 生命周期（草稿/已发布/已停用）、AI 授权开关、停用确认、失败重试；
- 全文搜索（按文字匹配，不使用 AI）与少量筛选（更多筛选折叠）；
- 版本历史（查看、恢复为新草稿）、来源记录；
- 客户视角问答测试入口（真实资料筛选、版本引用及资料不足提示）；开发阶段测试替身只验证程序链路，真实模型联调 B5 按用户决定待验证。原设计稿的模拟问答仅供交互参考，不计实现。

**后续批次（不在第一批）：**
- PDF / Word 等格式的自动解析（当前只登记原件、人工整理正文）；
- 跨产品的自定义字段设计器（第一批只保留简单默认模板）；
- 更多外部来源同步、多 Agent 各自授权的完整模型。

**明确不承诺：** 不承诺"任何文件都能自动变成可问答知识"；不承诺自动区分文件中的对内/对外内容。

## 9. 信息架构【建议】

```
卖家控制台
└─ 企业知识（统一入口）
   ├─ 全部知识            ← 默认视图
   ├─ 产品与服务          ← 预设筛选（内容形态 = 产品 / 服务）
   ├─ 文章与 FAQ          ← 预设筛选（内容形态 = 文章 / FAQ）
   ├─ 文件资料            ← 预设筛选（含原文件登记的知识）
   └─ 模拟客户问答        ← 测试工具（模拟客户视角）
```

- 「产品与服务 / 文章与FAQ / 文件资料」是**同一个列表的预设筛选**，不是四个互不相通的库；
- 分类（业务主题）只作为筛选条件出现，**不新增一级导航**。

侧栏导航的折叠形态（v0.1 本轮已确认修订）：
- 「产品与服务 / 文章与 FAQ / 文件资料」收进「全部知识」**可折叠分组**；三条子项各自带语义线稿图标（产品=盒、文章=书、文件=文件）；
- 主按钮「全部知识」点击=进入全部列表**并展开分类**（浏览与展开的主入口；高亮按当前视图，进入任一子视图后保持展开）；
- 主按钮右侧为**独立箭头按钮**：只展开/收起、不触发页面跳转。两个按钮并列，不嵌套；箭头带 aria-expanded/aria-controls，名称在"展开知识分类 / 收起知识分类"间切换；
- 首次默认**收起**；收起时子项不可 Tab 聚焦、屏幕阅读器不可访问（inert/aria-hidden 同步）；
- 展开/收起与箭头旋转动画 180–220ms；`prefers-reduced-motion` 下禁用动画；
- 展开状态保存在导航状态（render 不重置）；点击箭头只更新导航 class/aria，不整段重建，保证动画完整；
- 主/子导航跳转沿用未保存保护（有未保存内容时先弹三选一）；手机抽屉同样支持。

## 10. 页面设计与原型入口

通用布局：左侧为现有浅色控制台侧栏（与当前后台一致的视觉基准）；内容区 = 标题 + 主操作区 + 列表/正文；详情页 = 全页面正文 + 右侧轻量属性栏（不做窄抽屉写长文）。
原型入口统一为：`design/enterprise-knowledge-prototype/index.html`；
本地预览（开发者本机启动静态服务后）：`http://127.0.0.1:18868/`。

### 10.1 知识列表页
- 顶部：页面标题、一句话说明、新增入口——**「全部知识」视图保留通用「添加知识」下拉**（添加知识文章 / 添加产品与服务 / 上传文件）；**产品与服务视图只显示「添加产品 / 服务」、文章与 FAQ 视图只显示「添加文章 / FAQ」、文件资料视图只显示「上传文件」**，各自直达对应动作（不再出现通用下拉）；只读视角不出现任何新增入口（v0.1 本轮已确认修订）；
- 一条搜索框（**全文搜索：按标题与正文文字匹配，不使用 AI**）+ 分类筛选 + 状态筛选 + 「更多筛选」（用途、AI 可用性）；
- 搜索框右侧为线稿「×」**清空搜索**按钮：仅当有关键词时显示；点击只清空关键词（分类/状态等其他筛选保留）、立即刷新列表、焦点回到输入框；键盘可达（原生 button，Enter/Space，aria-label="清空搜索"）；输入框右侧留内边距避免文字被按钮遮挡（v0.1 本轮已确认修订）；
- 每行：类型标签、标题、（按需）原因小标、分类/用途/负责人/更新时间的元信息、**右侧仅一枚状态标签**；
- 整行可点进详情；空态提供"清空筛选"或"上传文件"的下一步。
- 原型：`index.html` → 默认视图；预览：`http://127.0.0.1:18868/`

### 10.2 文章详情 / 编辑页
- 详情：标题（含类型标签与状态标签各一枚）、负责人/更新时间/当前版本、不可用原因提示（辅助）、正文或 FAQ 问答对、来源与版本次级页签、属性栏；
- 编辑：标题、分类、用途、AI 授权勾选（发布后生效）、正文或问答对编辑、关联对象；「保存草稿」「发布」「取消」；
- 编辑已发布条目：保存草稿不改变线上版本；发布时对外+授权组合会出现一次确认。
- 原型路径同上；建议体验：列表点「发货与物流常见问题」或任一文章类条目。

### 10.3 产品或服务详情（结构化字段）
- 正文区上方是"该对象自己的字段表"：字段名 / 内容 / 单位 / 使用范围（对外·仅内部）/ 核准（已核准·待核准）/ 出处；
- 说明文字明确：字段是**这类对象自己的模板**，不是通用知识字段；
- AI 只引用「对外且已核准」字段；仅内部字段（如内部成本口径）永不参与回答。
- 原型：列表 →「3SV08NL007T 立式多级离心泵」或「GX-9 变频供水机组」（后者可演示"处理失败→重试"）。

### 10.4 文件导入页（3 步）
- 步骤条：1 选文件 → 2 检查识别内容 → 3 保存草稿或发布；
- 页内显式声明：**演示，不上传**——文件只在本地浏览器读取；TXT/MD/CSV 可预览；PDF/Word 登记原件并人工整理正文（后续批次才做自动解析）；
- 第 2 步所有识别内容可编辑（标题/正文/分类/用途）；第 3 步确认后保存草稿或发布（对外+授权的发布会再次确认）。
- 原型：列表右上「添加知识 → 上传文件」；本地预览地址同上。

### 10.5 来源与版本（详情内的次级页签）
- 来源列表：手动创建 / 文件导入（含原件登记信息）/ 引用说明；
- 版本历史：版本号、日期、作者、摘要、是否当前线上版本；历史版本可「恢复为草稿」（创建新草稿，不覆盖历史）；
- 固定提示：对外知识 ≠ 公开原文件下载。
- 原型："整机保修与售后响应政策"有 v1–v3 演示数据可用。

### 10.6 模拟客户问答页
- 页面显式声明：**演示，不调用模型**——答复由内置规则从演示资料生成；
- 只有「已发布+对外+已授权+有效+准备完成」的资料才可能被引用；管理员测试同样遵守（内部资料永不出现）；
- 答复附引用卡（资料名称 + 版本），点击可跳到资料详情；资料不足时显示“建议转人工”。内部测试页可向企业员工说明不可用原因，真实客户回复不披露内部资料名称、内部内容或处理诊断；
- 右侧规则说明：检索范围、字段级过滤、与全文搜索的区别。
- 原型：侧栏「模拟客户问答」；预览地址同上。

## 11. 逐步用户旅程

**旅程 1：整理一条 FAQ 并发布**
列表 →「添加知识 → 添加知识文章」→ 填写标题与问答对 → 选择用途（对外）→ 勾选"允许 AI 客服使用"（发布后生效）→ 保存草稿 → 列表出现「草稿」→ 继续编辑 → 发布（因"对外+授权"弹出一次确认）→ 条目变为「已发布（AI客服可用）」。

**旅程 2：修改已发布内容（v1 → v2）**
打开已发布条目 → 编辑 → 保存草稿（**v1 继续对外服务**，列表出现"有草稿修改待发布"提示）→ 发布 v2 → 短暂显示「已发布（AI客服不可用）」（原因：准备中）→ 准备完成后自动变为「已发布（AI客服可用）」。全程只影响这一条知识。

**旅程 3：停用与重新启用**
已发布条目 →「停用」→ 确认对话框（写明后果）→ 变为「已停用」→ 问答测试立即不再引用 → 「重新启用」→（对外+授权时需确认）→ 恢复「已发布」，短暂准备后可用。

**旅程 4：导入一份 TXT 文件**
「添加知识 → 上传文件」→ 选本地 TXT（≤1MB）→ 本地读取预览 → 检查并修正标题/正文/分类/用途 → 保存草稿 → 详情页可见"原文件登记"来源 → 后续人工核对、补充、发布。

**旅程 5：用客户视角测试授权范围**
侧栏「模拟客户问答」→ 点击建议问题或输入问题 → 命中可用资料：得到答复 + 引用卡 → 点击引用卡跳转到资料详情核对引用是否正确；命中内部/未授权/过期资料：得到"建议转人工"。

## 12. 状态与授权规则（核心）

发布前校验【建议】：标题与有效正文必填；FAQ 至少一组完整问答；产品/服务至少有已核准的有效资料。空正文、全空问答或没有可用字段时，不得因授权开关已开启就显示 AI 客服可用。真实检索的版本内容应与回答引用版本一致，演示的预置答案不证明这一点。

### 12.1 可用性计算（系统唯一权威）

```
AI客服可用 = 已发布
           ∧ 用途 = 对外
           ∧ 已授权（允许AI客服使用）
           ∧ 有效期内（未过期）
           ∧ 当前版本准备完成（无进行中/失败的处理）
```

| 展示文案 | 触发条件 | 详情辅助提示（不进入状态文案） |
| --- | --- | --- |
| 已发布（AI客服可用） | 上式全部成立 | — |
| 已发布（AI客服不可用） | 上式不成立 | 原因：仅内部 / 未授权 / 准备中 / 处理失败 / 过期（按固定优先级取第一条） |
| 草稿 | 未发布 | 辅助提醒：需要核对（若有） |
| 已停用 | 已停止 | 可重新启用 |

### 12.2 界面出现位置（防止重复与误读）

- 状态：列表一处 + 详情标题一处（同一枚）；**属性栏不显示状态**；
- 使用范围（对内/对外）：属性栏；编辑器里设置；
- 允许AI客服使用：属性栏开关（授权设置；调整立即生效；开启时如为"对外+已发布"需一次确认）；
- AI客服可用/不可用：由状态文案承载；原因是详情辅助提示。

## 13. 发布 / 更新 / 停用 / 恢复 / 同步失败与重试

| 操作 | 触发 | 结果 | 确认 |
| --- | --- | --- | --- |
| 保存草稿 | 编辑器中 | 草稿保存；已发布条目的**线上版本保持不变** | 无弹窗 |
| 发布（对内或未授权） | 草稿/详情 | 直接变为「已发布」（不可用原因按计算） | 无 |
| 发布（对外+授权） | 同上 | 弹出一次确认（列出后果）→ 发布 → 准备中 → 可用 | **对外AI发布确认** |
| 发布新版本 v2 | 已发布条目编辑后 | v2 处理完成前该条「不可用（准备中）」；其他知识不受影响 | 按上一条规则 |
| 停用 | 已发布条目 | 立即不可用；历史信息保留 | **停用确认** |
| 重新启用 | 已停用条目 | 恢复「已发布」；对外+授权时需确认；短暂准备后可用 | 对外+授权需确认 |
| 处理失败 | 系统处理失败 | 状态仍「已发布」，原因"处理失败"，出现「重试」 | 无 |
| 重试 | 失败条目 | 重新处理 → 完成 → 恢复可用 | 无 |
| 恢复历史版本 | 来源与版本页签 | **创建新草稿**（注明恢复自 vX），不影响线上版本 | 无 |

## 14. 权限

**已确认**：企业隔离；本企业账户默认可读内部与外部知识；AI 客服只用已授权的对外知识；新外部渠道默认关闭 AI、启用前确认资料。现有产品编辑权限保留；通用知识编辑、发布、授权的角色分工属于本稿建议。

**待评审**：具体角色矩阵（谁编辑、谁发布、谁授权、谁只读）与「默认关闭授权、仅管理员可开」等细节——**属于 P2，需用户确认后定稿**。

**原型中的表达**：原型提供"管理员 / 仅阅读成员"视角切换，仅用于演示"无权限者隐藏编辑操作并说明只读"的界面效果。**原型未验证后端权限隔离**；权限真正的强制点在后端检索与接口，不在界面。

## 15. 知识模型（业务描述，少术语）

- **内容形态**（这条知识"长什么样"）：产品、服务、文章、FAQ、文件来源。它决定编辑界面（结构化字段 / 正文 / 问答对 / 原件登记），是**内容本身的形式**。
- **主题分类**（这条知识"属于什么业务主题"）：如服务政策、企业文化、培训……**应可新增、可调整**；分类不决定内容怎么编辑。**内容形态与主题分类不应强绑定**。
- **在原型中的限制**：原型提供的是预置分类下拉（FAQ、服务政策、企业文化、培训、文件资料、产品、专业服务），**只是演示样例**；"分类自由新增/重命名"以及完整的通用 Schema 配置**未在原型中实现**，也不宣称已验证。生产上线前需要按业务确认分类体系（见 P7 邻域与 README 的限制说明）。
- **共同点**：无论形态，所有知识都属于企业、都可以有来源与版本、都可以设置用途与授权、都有生命周期。

## 16. 产品字段级授权、出处与版本

- 字段结构（原型演示）：字段名 / 内容 / 单位 / 使用范围 / 核准状态 / 出处；
- **字段级过滤（R14）**：条目对外 ≠ 整条字段对外。AI 只引用"对外且已核准"的字段；"仅内部"字段（例如内部成本口径）保留在同一页面供内部使用，但不会进入任何客户回答；
- 出处：每个字段可标注来源（如"系列目录 Rev.B"）；出处随字段展示在详情，便于人工核对；
- 版本：产品/服务条目与文章一样有版本历史；恢复历史版本创建新草稿。

## 17. AI 测试与未来多 Agent 边界

- **本批范围**：只做"客户 AI 客服"的对外授权（逐条 + 字段级过滤）；模拟客户问答用于验证授权范围与引用样式；
- **管理员测试约束（R9）**：内部资料即使管理员测试也不用于模拟客户回答；
- **未来边界【建议】**：同一知识层可被多个调用方（客户 AI 客服、内部销售助手、其他 Agent）使用，但**每个调用方用各自授权范围**——复用内容不等于复用权限；本批不实现其它调用方，不在现在承诺时间表。

## 18. 迁移保留关联（R5）

合并入口与数据迁移时保留：原产品 ID、已核准字段（含使用范围与核准状态）、来源记录、历史版本、推荐/询价关联。现有「推荐/询价」关联不因本次重构丢失；旧入口路径保留兼容（P1）。

## 19. 空态、报错、键盘、手机、未保存保护

| 场景 | 设计 |

| 报错 | 字段级错误（行内提示，如标题为空）；操作级错误（顶部汇总条）；处理失败（详情警示 + 重试按钮） |

## 22. 风险与未验证事项

1. **基础平台真实模型未接通**：本设计不声称通用问答已实现；B5 在模型接通前保持"未验证"。
2. **原型未验证后端隔离**：界面层的隐藏不等于权限强制；B1/B2 必须由后端实现与测试兜底。
3. **分类体系未定**：原型分类为示例；若不做"分类可新增"的收敛设计，迁移期容易混乱。
4. **处理中/重试的过渡体验**：真实处理时间与失败率未知；原型仅为交互示意。
5. **导入质量**：混合文件的内外区分仍依赖人工；误发布对外内容的风险通过"对外AI发布确认 + 字段级过滤"降低，但不能归零。
6. **角色权限（P2）未定**：在角色矩阵确认前，不要开发依赖具体角色的强制逻辑。

## 23. 竞品研究启发（引自既有研究，不再展开）

出自 `docs/research/2026-10-10-企业知识管理市场与竞品研究.md`，本设计借鉴其四点判断：
1. **Intercom（统一来源）**：一个内容入口服务员工与 AI，同时用"AI 可用性"逐条控制——对应本设计的统一入口 + 逐条授权。
2. **Guru（核对）**：知识要有负责人、核对标记与使用反馈——对应"需要核对"作为草稿辅助提醒与其所有者信息。
3. **Dify（可用准备）**：原始内容与 AI 处理流程分开、可观察处理状态——对应"准备中/处理失败/重试"的可见性。
4. **Directus（灵活类型）**：不同内容类型可有不同字段与关系——对应"内容形态 × 结构化字段"并存，以及"字段不是通用模板"的立场。
