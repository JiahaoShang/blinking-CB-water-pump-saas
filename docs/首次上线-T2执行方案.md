## 1. 目标、范围与启动条件

目标：在本机、用**合成测试企业/资料**验证两条真实模型链路的运行边界，取得可审计证据：

- 平台模型服务（DeepSeek）：连接、协议契约、JSON 输出校验、失败分类与重试、引用与版本、生成期间撤权、AI 默认关闭、密钥卫生。
- 企业自定义 API（公网 HTTPS OpenAI 兼容）：同上序列的分阶段复验；配置存储与隔离另由现有测试覆盖（见 §3.2）。

明确不包含：正式部署（T4）、真实官网/渠道账号联调（T5/T7）、企业真实资料与内部核准（T3）、共享 Dify 恢复（继续保持关闭）、产品行为或界面修改。

用户前置条件（均不可由执行方代做）：

1. 在本机 shell 或服务的运行环境安全配置 `AI_MODE=deepseek` 与 `DEEPSEEK_API_KEY`（只在配置时输入；不写入仓库、文档、日志、截图或命令行）。
2. 确认真实调用的**费用授权与上限**：脚本默认上限 6 次、硬上限 12 次；单次输出 ≤512 tokens（可经 `DEEPSEEK_MAX_TOKENS` 收紧）。
3. 若要测企业自定义 API：提供可直连的公网 HTTPS OpenAI 兼容端点与模型名，并把该密钥放入一个环境变量（默认 `B2B_T2_CUSTOM_API_KEY`）。

不需要真实企业资料：脚本自行在系统临时目录合成临时企业与资料，结束时销毁。

## 2. 交付物与用法

脚本：`tools/pilot_checks/check_first_launch_t2.py`（只复用现有测试夹具与产品函数，不改产品代码）。

```text
# 阶段 0：干跑（默认；完全离线、不产生费用；任何真实调用会被监视器拦截为失败）
python3 tools/pilot_checks/check_first_launch_t2.py

# 阶段 1：真实平台服务（需先安全配置 AI_MODE / DEEPSEEK_API_KEY）
python3 tools/pilot_checks/check_first_launch_t2.py --live --stage platform \
    --out /tmp/b2b-t2-live-platform.json

# 阶段 2：企业自定义 API（密钥只从环境变量读取；命令行不要放密钥）
B2B_T2_CUSTOM_API_KEY=... python3 tools/pilot_checks/check_first_launch_t2.py --live \
    --stage custom --custom-base-url https://api.example.com/v1 --custom-model example-model \
    --out /tmp/b2b-t2-live-custom.json
```

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--live` | 关 | 显式开启真实调用；不开=干跑，永不外呼 |
| `--stage` | `platform` | `platform`=平台服务（环境变量）；`custom`=企业自定义兼容接口 |
| `--steps` | `probe,grounded,no_basis,revoke,fault` | 子集可选，用于分阶段（如首日只跑 `probe`） |
| `--ground-kind` | `knowledge` | grounded/revoke 步骤使用的证据类型（knowledge/topic/item_field/product_field，逐类可分次跑） |
| `--max-calls` | 6 | 真实调用上限（1–12）；计划步数超过上限时预检直接拒绝，不发起调用 |
| `--out` | 无 | 报告 JSON 路径；**live 必填**，保留可审计状态/引用版本/用量 |
| `--custom-key-env` | `B2B_T2_CUSTOM_API_KEY` | 读取自定义密钥的环境变量名（密钥不进命令行） |
| `--keep-workdir` | 关 | 保留临时目录与合成数据库副本供检查 |

live 五步（每步消耗 1 次调用，真实调用按脚本内计数器记账，超限即拒绝继续）：

1. `probe`：合成需求文本 → 需求抽取（连通性 + JSON 契约 + 白名单/单位校验）。
2. `grounded`：合成问题 → 统一问答入口/产品字段入口 → 期望有据回答（服务端精确引用 + 真实版本）。
3. `no_basis`：无依据问题 → 期望不编造（模型判 none / 资料不足）。
4. `revoke`：真实模型返回后、平台复核前立即撤权被选证据 → 期望"生成期间已失效"拒答。
5. `fault`：用不存在的模型名触发真实错误 → 期望归类为已知失败状态、不产生任何答复。

退出码：`0`=全部通过；`1`=存在 FAIL 或 REVIEW；`2`=用法/配置问题（未发起任何调用）。**REVIEW** 语义：平台语义正确（未编造、引用为服务端原文）但真实模型行为与预期不一致（如把问题答到同类另一条合格证据上）——必须人工评估，不自动当通过，也不当平台缺陷。

报告 JSON 内容包括：脚本 SHA256、Python 版本、护栏信息（临时目录、`AI_MODE` 取值、Dify 变量名披露、干跑监视器清单）、每步状态/耗时/HTTP/tokens/引用版本（kind、version、version_id、quote）、真实调用记账（第 N 次、动作、时间）、临时库 `ai_call_log` 全量导出、用量汇总与注意事项。写入前脚本会断言报告中不含已知密钥值（只与内存中的键值比对，不扫描文件系统）。

运行位置纪律：在**不含原 `data/`、`.git`、虚拟环境的临时代码副本**中运行（或至少确认无业务数据目录）；脚本全部数据写系统临时目录，不读不写仓库 `data/`，会前后比对 `data/` 状态并在被改动时判 FAIL。不发送外部消息、不恢复 Dify、不读取也不扫描密钥文件。

## 3. 逐项验收内容（现有测试 / 真实联调缺口 / 本脚本覆盖）

以下"现有测试"均指已合入仓库、可复跑的本地程序测试；"缺口"是真实联调前无法由这些测试替代的部分。

### 3.1 真实模型平台服务（DeepSeek）

- 验收点：真实连接与鉴权；响应契约（`finish_reason=stop`、JSON 对象、usage）；失败分类（401/402/429/5xx/超时→内部状态与处理建议）；错误不产生假结果。
- 现有测试：`test_ai_deepseek.py`（本地模拟服务覆盖成功/无效输出/超时/429/401/5xx、重试恢复、日志不含密钥，协议级真实 HTTP）；`tools/pilot_checks/check_deepseek_live.py`（最小真实连接探针，人工执行）。
- 真实联调缺口：从未连接真实 DeepSeek 账户；真实 402（余额不足）、真实限流、本机网络出口（如需代理）未验证。
- 本脚本覆盖：live `probe`（连通+抽取契约）+ `fault`（真实错误分类）+ 报告留痕。

### 3.2 企业自定义 API（OpenAI 兼容）

- 验收点：整企业生效、仅管理员可配置；地址校验（公网 HTTPS、不含凭据/查询、不跟随重定向、失败不切回平台）；测试连接成功才原子替换；故障不静默切换；私有目录 700/600、密钥不进 SQLite/审计/页面；断开恢复平台。
- 现有测试：`test_model_settings.py`（企业隔离、重启持久化、文件权限、密钥不回显、坏配置拒绝、失败保留旧配置、官网业务路由与断开恢复的真实 HTTP 流程）。
- 真实联调缺口：真实兼容供应商端点（DNS 公网校验、TLS、无重定向）、真实密钥未联调。
- 本脚本覆盖：干跑用**假密钥**验证存储权限/回显/数据库与日志卫生；live `--stage custom` 跑与平台相同的 probe/grounded/no_basis/revoke/fault 序列（配置只在内存构造，**不把真实密钥落盘**）。
- 限制：脚本不调用产品内"连接即保存"（`EnterpriseModels.save`）的真实密钥落盘流程——该流程由现有测试以假密钥覆盖，正式管理员在设置页的真实连接动作留 T4/T7 环境复验。

### 3.3 官网与渠道统一证据入口

- 验收点：官网买方会话与已开启渠道共用同一过滤与问答阶段（`answer_question_prefer_dify`，app.py:4687）；渠道默认 AI 关闭时不进入模型；产品字段问题不被知识阶段劫持。
- 现有测试：`test_enterprise_knowledge_task4.py`（统一入口、渠道关闭/开启、字段问题不被劫持、跨企业）；`test_knowledge_phase2_ai_gates.py`（仅有主题的企业）；`test_channel_runtime.py`、`test_business_channels.py`（渠道运行）。
- 真实联调缺口：真实渠道账号/官网 HTTPS 嵌入属 T5/T7；真实模型下的统一入口未联调。
- 本脚本覆盖：干跑直接调用统一入口函数（知识问题 grounded、渠道 `ai_disabled`、渠道开启后 `answered`）；live 的 grounded/no_basis/revoke 均经统一入口；不启 HTTP 服务（HTTP 层由现有测试与 T5/T7 真实部署覆盖）。

### 3.4 四类证据与版本引用及限制

- 四类合格证据（每一类都是一个"来源→发布→授权→检索→引用"的完整链）：
  - `knowledge`：第一批文章/FAQ/产品与服务；条件=已发布+对外+已授权+未过期+当前版本准备完成；回答=存储原文精确引用；引用=真实版本（`vN` + `version_id` + 发布时间）。
  - `topic`：第二批主题段；逐段过滤（已核对、出处钉住版本不静默升级、到期即出）；人工撰写段须核对；引用=主题版本 `topic_version_id`。
  - `item_field`：第二批灵活字段；条件=已核对+允许客户引用+有值（0/否是有效值）+有来源；改值/改单位/改来源使核对失效。
  - `product_field`：产品字段；条件=产品已发布+逐字段核准+对外+有值+出处可用+产品已开启 AI 客服授权（可设到期）。
- 限制（现有行为，联调时同样成立）：送模型候选 ≤24 条（`KNOWLEDGE_QA_EVIDENCE_LIMIT`）、单条文本截断 800 字符；模型只做选择，答案与引用由服务端生成；选择不在候选内→按资料不足；资料不足只建议转人工，不自动建人工任务。
- 现有测试：`test_enterprise_knowledge_task4.py`（逐字段核准/出处、精确引用+真实版本、模型 none/未知键、企业隔离）；`test_knowledge_phase2_ai_gates.py`（混合主题只返合格段、来源换版不静默升级、到期复核、字段 0/否与闸门、撤权复检）；`test_enterprise_knowledge_review_items15_19.py` 等。
- 真实联调缺口：真实模型在合成语料之外的选择质量；真实业务内容的候选上限行为。
- 本脚本覆盖：干跑四类各一条 grounded，断言引用类型/精确原文/版本行（product_field 另核字段与版本号）；live 用 `--ground-kind` 逐类分次复验（同一批候选里同时存在四类，模型选择本身就是一次跨类判别测试）。

### 3.5 故障输入保留

- 验收点：模型失败不丢输入、不产生假答复、可直接重试；失败写入 `ai_call_log`（状态与处理建议，不含消息与密钥）。
- 现有测试：`test_ai_deepseek.py`（买方消息/问题保留、同键重试、失败不假装成功）；`test_enterprise_knowledge_task4.py`、`test_knowledge_phase2_ai_gates.py`（问答失败状态、不建任务）。
- 真实联调缺口：真实供应商故障（401/402/429/5xx）从未在真实账户触发。
- 本脚本覆盖：干跑 stub 失败→error+日志+同题重试成功；live `fault` 步用无效模型名触发真实错误分类，其后 `probe` 用同一抽取输入成功（输入未丢失、可重试）。

### 3.6 生成期间撤权

- 验收点：模型返回后平台再次复核；生成期间发生停用/撤权/到期/换版/字段变化→按资料不足处理，绝不输出已失效内容。
- 现有测试：`test_enterprise_knowledge_task4.py`（并发撤权、字段来源变更）；`test_knowledge_phase2_ai_gates.py`（主题撤权/换版/到期、字段值变化，含"模型等待期间"钩子复现）。
- 真实联调缺口：真实模型延迟窗口（秒级至数十秒）内的撤权从未演练。
- 本脚本覆盖：干跑四类各一次"模型选择后立即撤权"（类型对应的真实撤权动作）；live `revoke` 步在真实模型返回后立即撤权，期望 `no_evidence`+"生成期间已失效"。

### 3.7 AI 默认关闭确认

- 验收点（默认值，联调前先确认现状）：`AI_MODE` 默认 `rules` 且 deepseek 缺 Key 拒绝启动；第二批批次/资料默认仅内部+AI 关（`kb2_create_batch`/`kb2_save_batch_settings` 默认）；第一批资料默认对内未授权（`create_knowledge_item` 默认）；主题/资料"对外+AI"发布需显式确认；产品字段 AI 客服授权默认关闭（侧车）；渠道账号 `ai_enabled` 默认 0；共享 Dify 对外生成保持关闭（`dify_ask_question` 当前无调用方）。
- 现有测试：批次确认路径（`test_knowledge_phase2_batch_publish_confirm.py`）、旧发布闸门（`test_knowledge_phase2_legacy_publish_gate.py`）、渠道默认关（`test_enterprise_knowledge_task4.py`）、模型设置（`test_model_settings.py`）。
- 真实联调缺口：正式部署的实际默认值（服务进程环境、企业开关）在 T4 复核。
- 本脚本覆盖：干跑断言两批资料默认值、产品授权开关、渠道默认 `ai_disabled`、`AI_MODE` 缺省与缺 Key 拒启、DIFY_* 变量存在也不改变路径、三类不合格负例不进候选。

### 3.8 秘密检查

- 验收点：密钥不进 SQLite/审计/页面/日志/报告；`<db>.model-secrets/` 目录 700、文件 600；`AIConfig` 表示遮蔽密钥；自定义接口不打印。
- 现有测试：`test_model_settings.py`（权限、页面与 DB 字节无密钥）；T1（文件权限与短写完整性，282 项独立验证）。
- 真实联调缺口：真实密钥接入后的实际输出卫生（报告与 `ai_call_log` 导出）。
- 本脚本覆盖：干跑假密钥（配置表示遮蔽、私有目录权限、SQLite/审计/调用日志断言）；live 在写报告前断言报告文本不含内存中的真实密钥；报告导出 `ai_call_log` 供人工复核（无密钥、无消息内容）。

### 3.9 本轮核对发现的既有实际阻断（登记；修复在并行任务处理，本任务不改产品代码）

以下两项由并行独立复现任务登记（证据见 `docs/evidence/first-launch-t2/` 内非本任务产物），本任务经直接读码复核成立；**T2 live 执行前必须先修复并取得回归证据**：

1. **统一入口吞掉知识阶段的模型故障**（影响 §3.3 统一入口与 §3.5 故障输入保留）。复现条件：企业只有合格主题证据、`select_knowledge_evidence` 抛 `AIUnavailableError`（如 timeout）时，`answer_knowledge_question` 返回 `error`，但 `answer_question_prefer_dify` 没有错误分支，直接把第一段结果（`needs_human / 没有可引用的已发布产品版本`）当正常结果返回（app.py:4715-4719）。后果：官网/渠道侧表现为"资料不足"而非可重试故障，买方输入与同键重试语义被绕过。验收要求：模型故障应沿既有 503 + 输入保留 + 同幂等键重试路径传播，且不产生假答复、不重复模型调用。
2. **问答测试页主题/灵活字段引用链接 404**（影响 §3.4 的界面呈现）。`/admin/knowledge/qa` 对非产品字段引用一律拼 `/admin/knowledge/item/{item_id}`，而主题引用没有 `item_id`（只有 `topic_id`），生成 `/admin/knowledge/item/` 空链接（enterprise_knowledge_ui.py:1220 附近）。验收要求：主题/灵活字段引用给出可访问的对应详情链接与来源标签。

本任务不实施上述修复（属并行最小修复任务）；修复落地后，本方案的 dry-run 与 live 步骤应在**修复后的代码**上重跑，作为 T2 验收的一部分。

## 4. 执行步骤与通过标准

建议顺序（可分多窗口完成）：

1. 复制代码到不含 `data/`、`.git`、虚拟环境的临时副本 → 跑干跑全绿（本方案 §5 已执行）。
2. 用户完成后：安全配置密钥与费用授权 → `--live --stage platform`（可用 `--steps probe` 先探连通）→ 全绿。
3. 可选：`--stage custom` 复验企业自定义端点。
4. 归档：报告 JSON 与日志存入 `docs/evidence/first-launch-t2/`（含脚本 SHA256、Python 版本、退出码；不存密钥）。

通过标准：干跑无 FAIL/REVIEW；live 无 FAIL（REVIEW 项人工评估并记录结论）；报告与 `ai_call_log` 均不含密钥；`revoke` 步得到"生成期间已失效"；报告中的引用类型/版本与合成资料一致。
