# GitHub 同步与本地测试规则

生效日期：2026-10-14（用户明确决定）。适用于本仓库全部分支。

## 1. GitHub 版本范围

GitHub 仓库只包含以下内容：

- 项目运行代码与静态资源；
- 部署/运维工具：部署、备份、恢复、建号（创建管理员）、资料核准工具；
- 依赖清单（如 `requirements-knowledge.txt`）与项目文档：需求、架构、运维、状态类文档。

测试程序（包括可复用回归）、测试驱动/模拟器、合成夹具、本地演示与原型、测试证据/日志/截图均只保存在本机开发环境，不推送 GitHub。

本轮清理覆盖当时存在的四个分支（feat/mvp-foundation、main、feat/app-flow、feat/domain-rules）：凡在分支上被跟踪的本地测试资料已取消跟踪；旧 Git 提交保留，不做历史抹除。本次调整不代表服务器已更新，也不代表产品已正式上线。

## 2. 必要测试继续执行

- 留在本机的测试必须继续执行。不能因为 GitHub 仓库没有测试文件而跳过测试，也不能以「克隆里没有测试」为理由宣称测试通过；验收以真实执行结果为准。
- 现有 `test_*.py` 等测试文件可以继续在原位置运行；新写的测试放在 `.local-development/`、`tests/` 等被忽略的路径。
- 本地测试在 GitHub 没有备份：今后开发前维护本地测试备份；新克隆或换另一台开发电脑时，必须从本地备份单独安全复制本地测试套件与夹具（不从 GitHub 获取）。这是本规则的已知限制。

## 3. 提交与推送前检查

- 每次提交/推送前检查 staged files 与待推送提交树中每个文件的用途，确认不含测试、证据与本地资料。
- 禁止使用 `git add -f` 重新把测试文件加入 Git。
- `.gitignore` 只阻止普通误加入，不是强制权限控制；不得声称它无法绕过。

## 4. 运行与发布的边界

- 当前分支（feat/mvp-foundation）的应用运行/发布不依赖测试文件；测试文件缺失不影响应用运行与发布。
- 旧 main 的演示功能依赖的夹具与网关已本地化：新克隆不含这些演示入口；main 仍是历史旧业务版本，不能作为当前上线版本。
- 审核与验收文档可以保存结论和本地证据的相对位置；`docs/evidence/` 等链接只在拥有本地证据的开发环境有效，GitHub 中不会提供这些证据文件。
