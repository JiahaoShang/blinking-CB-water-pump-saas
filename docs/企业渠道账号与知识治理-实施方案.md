# 企业渠道账号与知识治理

日期：2026-10-09。来源：用户在本轮明确确认六条规则，并要求按建议顺序开始开发。状态：需求已确认，实施中；不是已验收。

## 已确认规则

1. 接入账号均作为企业业务账号，由企业所有；成员只关联和使用账号。
2. 企业管理员管理全部连接及成员权限；获授权成员管理自己关联的连接。平台负责隔离、原账号收发和审计，企业负责人员安排。
3. 企业管理员查看本企业全部业务会话；员工仅查看自己关联账号授权范围及明确转交给自己的业务历史。模块权限不替代对象授权。
4. 同企业成员默认可读内部和外部知识；修改、核准与发布仍需模块授权。对外 AI 只能使用已核准且允许对外的知识。
5. 新连接默认关闭 AI；开启时弹窗提醒确认用于问答的企业资料，取消不生效。账号接通不自动开启 AI。
6. 管理员可选择原负责人、接替人并转交客户、关联 RFQ 和未完成跟进。接替人获得相关历史访问权；保留原负责人、历史操作者和转交审计。

## 实施约束与决定

- 复用现有工作树、Python/SQLite、会话/RFQ/线索，避免新增一套客户与知识真值。
- 渠道账号成为独立对象；会话、客户身份、去重和出站都携带连接 ID。旧数据迁移保留 ID、消息、配置与操作人；未关联人员的历史数据仅管理员可见，不能猜测归属。
- 账号关联授权不扩大模块权限；客户转交不自动授予原账号的连接管理或发送权限。
- 员工授权撤销即时生效；员工不得修改自身授权、负责人或其他人的连接。
- 原会话客户身份作为当前客户转交单元；同一客户跨账号关联未经核准不自动合并。转交关联该客户会话的 RFQ、线索和未完成跟进，历史事实不重写。
- LangBot/Dify 只作后台组件；企业界面展示平台、账号、连接状态、AI 状态和知识状态，不展示内部编号、地址、密钥或组件名称。
- Telegram 仍按机器人授权，WhatsApp 桥按扫码授权；不宣称所有平台支持个人账号登录。同平台多连接须由后端服务实际支持，不能以保存记录代替连接成功。
- 内部知识禁止进入对外检索；资料撤回/权限收紧即时限制回答，不等待异步同步。知识版本和出处保留。
- 知识同步自动执行，失败重试；只有索引完成才称为可用。跨企业知识隔离不依赖模型自行判断。
- F-25 官方 WhatsApp 嵌入式注册和第三方资质仍独立暂缓，本轮不虚构或绕过外部开通条件。

## 切片与验收

1. 账号与权限：同企业两个连接互不覆盖；员工对象授权与模块授权双检查；跨企业拒绝；旧库可迁移。
2. 收发路由：同一客户联系两个账号不会混会话；外部消息 ID 按连接去重；回复回原账号；一个账号停用不影响另一个。
3. 客户转交：管理员界面选择双方并转交；RFQ、未完成跟进随客户移交；历史可见但发送仍需账号授权；失败不产生部分转交。
4. 连接界面：平台账号卡片、自助连接、AI 默认关、开启确认弹窗、暂停 AI 仍接收消息、解绑独立。
5. 知识：成员只读入口；内部/外部标记；只外部核准知识供 AI；自动同步与可信状态；撤回后新回答不引用。
6. 真实本地界面与模拟服务端到端验证；实际外部账户联调只在所需条件可用时执行并单独记录。
