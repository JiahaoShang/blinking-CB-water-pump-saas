# 企业渠道账号与知识治理开发计划

**Goal:** 将企业共享单渠道配置升级为按企业账号授权、隔离、原路收发的业务流程。

**Architecture:** 保留现有业务真值和 Python/SQLite。账号治理独立模块处理数据迁移、对象授权和客户转交；HTTP 入口及既有渠道总线调用它。

**Spec:** 企业渠道账号与知识治理-实施方案.md。用户已明确要求在本工作树开始开发，直接在当前会话执行，不重复请求开发授权。

## 文件职责

- `business_channels.py`：账号数据迁移、连接授权、会话访问和客户转交。
- `app.py`：既有 API、收发总线、卖家界面、知识读取和同步。
- `test_business_channels.py`：迁移、权限、同平台双账号、AI 默认关闭和转交测试。
- 受影响旧测试：调整被本轮明确改变的共享访问与扫码自动 AI 语义，不降低隔离或收发断言。
- V1、数据模型、技术架构、状态记录：同步确认决定与实际验证。

## 重点检查

- 跨企业账号 ID、客户 ID 和员工 ID 被篡改时拒绝且不写入。
- 管理员撤销授权或停用成员后，旧页面发出的 POST 也拒绝。
- 同外部用户和消息 ID 在不同连接下独立；重试不重复发送。
- 转交历史不改原外部账号，不绕过发送授权。
- 知识同步失败/索引未完成/撤回时不错误显示可回答，不允许内部资料泄漏。
